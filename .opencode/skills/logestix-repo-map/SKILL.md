# logestix repo map

Per-file inventory of `libs/`, `apps/` and `tests/`, grouped by family and
subsystem. Brace globs like `{a,b}` or `_v41_*` denote a group of files that
share one description; every other bullet names one file. The compact top-level
map lives in AGENTS.md; this file is the detail.

**Machine-checked equivalents — the source of truth when prose disagrees:**

- `test_model_suite_guard.cpp::Suites()` — model → lifecycle stages → ctest targets.
- `test_model_independence_guard.cpp::kPassports` — model → passport header → owning namespace.
- `test_model_independence_guard.cpp::kLifecycle` — model → the TU(s) forming its generation path, each asserted to wire residency lock, streaming/abort, context teardown, a governor lease, `output_text`, `weight_resident_bytes`, and to mutate session state inside the lock.
- `test_code_naming_guard.cpp::SchemeRegex()` / `AllowedCommon()` — file-naming vocabulary.
- `test_ctest_labels_guard.cpp` — every test target carries a label.

Model ingestion itself (the 8-stage protocol, naming scheme, guard registries to
extend) is the `ingesting-a-model` skill; build wiring is
`cuda-cmake-build-gotchas`; running/operating the engine (apps, vault paths,
env knobs) is `running-a-model`; throughput work is `perf-tuning-a-model`.

  - Kimi decode is built on two nsys measurements (2026-09-14): H2D 203 ms/token (routed misses 277/token × 24.78 MiB over PCIe at **57 GB/s** — the bus ceiling, + shared 84 ms ON THE COMPUTE stream) and 141 ms/token in kernels (71% — `Nvfp4DequantKernel`, materializing bf16). Hence two levers: (1) **copy/compute overlap** — per-entry readiness `ready_slot[8]` (`KimiMoeCacheBatch::wait_miss_pos` says which upload gates the entry) + per-slot last-read `slot_read[slots]` instead of the batch-wide fence that made the copy stream wait for ALL compute; (2) **shared-expert device arena** (61 layers × `KimiSharedSlabLayout` = 1441 MiB, loaded once, `KimiSharedSlotView` uses the same layout function as the upload) — removes the per-layer pageable H2D 84 ms. Remainder: `LSX_KIMI_TC=1` (W4A4) is not enabled because of the numeric root cause; the next lever is eliminating dequant via the model-neutral NVFP4 GEMV (71% of kernel time). **The LFU cache policy (frequency-eviction + ageing) was tested and REJECTED (2026-09-14)**: on 128 tokens it gives +15% (4.7→5.4 t/s), but on a long run it regresses (3.7 t/s and early EOS at 1386 tokens instead of 2048) — LFU evicts recently read "rare" slots, so the copy stream constantly waits on the last compute's `slot_read`; plus output-stream divergence. Reverting to LRU reproduced 2048 tokens @5.1 t/s bit-for-bit (398.4 s). Only retry with a fence-compatible rule (accounting for "last read time" when choosing a victim) and mandatory validation at 2048 tokens. For offline policy analysis — the env hook `KIMI_TRACE_FILE=<path>` in `KimiLayerStack` (writes {turn,layer,top-8} per decode layer; on a real 125-token trace LRU = 283 misses/token, offline optimum Belady = 158 with 748 slots)
