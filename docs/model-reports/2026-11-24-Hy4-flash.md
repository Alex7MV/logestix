## Part 1 — publish-ready post

### What was converted, and where it was run

**Hy4-flash** (tencent/Hy4-flash) is a 220-billion-parameter mixture-of-experts
model — 155.5B text backbone, 63.5B of n-gram memory ("Engram"), a 0.43B vision
encoder and a 0.85B speculative drafter — with 11.3B parameters active per token
and a 1M-token context. Its 42-layer backbone interleaves sparse attention
(12 layers, 32 heads) with sliding-window attention (30 layers, 64 heads, a
512-token window) at a 1:3 ratio, runs routed experts in a **1536-wide latent
space** instead of the model's 3072-wide hidden space, and carries four residual
streams through "identity Hyper-Connections" rather than one.

Hardware: one RTX 5090 (32 GiB, SM 12.0), 768 GB host RAM, 160 hardware threads,
CUDA 13.5 toolkit on a 13.4 driver.

Artifact: **83 GB** under `<model>/logestix/` — 1232 pinned dense tensors (4.8 GB)
plus 20 992 routed experts (41 MoE layers × 512, 78 GB), 4-bit weights with norms,
biases, sinks, the router and the hyper-connection parameters held at source
precision. Engram, the vision tower and the speculative drafter are cut and
counted (`deferred: engram=164 vision=441 dfly=87`). Routed experts stay on host as
memory-mapped views behind a bounded LRU with a device slot cache, which is what
lets a 220B model answer inside 32 GiB of VRAM at all.

### What the checkpoint forced into the engine

1. **Two attention regimes in one stack, with different head counts and different
   RoPE bases.** Layers 0–1 and every layer with `l % 4 == 1` run sparse attention
   (32 heads, θ = 1e7); every other layer runs sliding-window attention (64 heads,
   window 512, θ = 1e4). A single attention shape across the stack cannot even
   load both weight sets.
2. **Hyper-connections in their "identity" form.** Four residual streams, an
   8-row mix matrix producing four `pre` gains and four `post` gains, magnitude
   2.0 — and **no Sinkhorn iteration and no combine matrix**, unlike the
   DeepSeek-V4 lineage this architecture otherwise follows. The residual update is
   `streams_j = post_j · y + streams_j` for every stream `j`, i.e. the *same*
   sublayer output scaled per stream, not a mixture.
3. **Sandwich norms on the sublayer output**, two of them per layer
   (`post_proj_norm` after attention; `post_fc2_norm` on the single dense layer and
   `combine_output_norm` on all 41 MoE layers). Normalizing the residual instead is
   the natural misreading and changes every layer.
4. **LatentMoE.** The experts read a 1536-wide projection of the block input and
   write a 1536-wide latent sum, which a second projection lifts back to 3072; the
   shared expert and the router both read the **full-width** input. The per-expert
   matrices are therefore `[2·1536, 1536]` and `[1536, 1536]`, not sized by
   `hidden_size`.
5. **A sink in every softmax.** Each head carries one learned logit that joins the
   softmax denominator and is then dropped, so the attention weights sum to less
   than one by design. Treating it as a bias (or ignoring it) is a silent rescale.
6. **Gated MLA.** The attention output is multiplied by a sigmoid of a separate
   full-width projection before the output projection.
7. **Interleaved rotary pairs, not the half-split rotation** that Llama-style
   implementations use: the reference pairs lanes `(2j, 2j+1)` and broadcasts one
   frequency onto both. This is the single easiest error to make here, and getting
   it wrong still produces fluent text.
8. **`rms_norm_eps = 1e-5`**, not the DeepSeek lineage's `1e-20` and not the
   sibling `hy_v4`'s `1e-6`.
9. **Engram is not applied.** 126.7 GB of n-gram tables on layers 1/11/21/31. The
   reference does implement it — the hash multipliers are drawn from a seeded
   RNG rather than shipped as weights — so this is a scope decision, not an
   unknowable, and it is recorded as the highest-value follow-up.

Reference used: the implementation the checkpoint's own README pins,
`huggingface/transformers` PR #50903 (`models/hy_v4_flash`). **The initial
stage-0 triage concluded that no such implementation existed and that reference
parity was impossible without guessing; that conclusion was wrong**, and the
harness now in `tools/hy4_flash_reference.py` loads all 1230 text-backbone
parameters from the checkpoint and runs it.

### Artifact-level traps found in the checkpoint

1. **`engram_layer_ids` is 1-based.** The config lists `[2, 12, 22, 32]`; the
   engram tensors and the model card put those four layers at 1, 11, 21, 31. The
   reference compensates with `layer_idx + 1 in config.engram_layer_ids`. A
   converter that trusts the list verbatim cuts the four wrong layers, succeeds,
   and produces a model with four instead of zero uncut memory layers. *Suggestion
   to the authors:* state the indexing convention in `config.json` or emit
   0-based ids as every other layer list in the file does.
2. **The checkpoint's tensor names are not the reference's module names.** Fourteen
   renames (`learnable_sink_param`→`sinks`, `linear_gate`→`gate_proj`,
   `routed_expert_down_proj`→`pre_expert_proj`, `hc_attn_layer.hc_pre.hc_fn`→
   `attn_hc.fn`, …) live only in the transformers `conversion_mapping.py`. Loading
   with the raw names leaves 422 parameters at their random initialisation — no
   error, no warning, and fluent garbage out. *Suggestion:* ship a
   `conversion_map.json` beside the weights.
3. **The chat frame is load-bearing.** `"The capital of France is"` fed as raw
   token ids does not continue with a capital city — both the reference and this
   engine answer off-distribution. Only the `<｜hy_start:opensource｜>{role}…` frame
   asks the question the model was trained on. Any harness comparing raw-prompt
   continuations across this family will "discover" a model that cannot answer.
4. **`reasoning_effort` defaults to `high`.** The template's default opens a
   thinking block, so a serving path that does not pass `no_think` gets a reasoning
   monologue before the answer. This engine defaults to `no_think` and exposes
   `LSX_HY4_REASONING_EFFORT=high` for the other mode.
5. **Two RoPE bases and two head counts are declared per layer type, not per
   model.** `rope_parameters` is keyed by `sliding_attention` /
   `deepseek_sparse_attention`; `swa_num_attention_heads` sits beside
   `num_attention_heads`. Reading only the top-level fields silently gives the
   sparse layers the sliding layers' rope and head count.

### What was not measured, and why

* **Decode throughput.** No t/s number at all. The artifact exists and the decode
  path runs, but a throughput number for a model whose outputs are wrong would be
  a number about the wrong computation.
* **Reference parity beyond the first token.** One reference step costs 13 minutes
  wall on this host (155B parameters in bf16 streamed from RAM, and the harness
  feeds the full prefix each step), so a systematic layer-by-layer bisect needs the
  `DynamicCache` path first.
* **FSI/CODE/DET.** Deliberately not captured: a golden taken from a reference the
  engine disagrees with would turn one known gap into three red gates.
* **Long-context behaviour.** The sparse indexer's group selection is implemented
  (pooled gated keys, top-512 groups, own-group always recalled) and is exercised
  at short context only; the first context beyond 2048 tokens has not been run.
* **Engram.** Cut, not measured.

### The reference, and the correction to stage 0

Stage 0 concluded "no published implementation exists (transformers ships `hy_v4`,
not `hy_v4_flash`)". That was true of `transformers` **main** at the time and false
of the ecosystem: the checkpoint's README pins
`refs/pull/50903/head`. The oracle written against that wrong conclusion
(`tools/hy4_flash_oracle.py`) is kept as documentation of the semantics and marked
exploratory; `tools/hy4_flash_reference.py` is the reference of record and carries:

* the PR's `conversion_mapping.py` `hy_v4_flash` rename list (14 rules), without
  which 422 parameters keep random values — verified: `loaded: 1230 missing: 422`
  before the fix, `loaded: 1230 missing: 0` after;
* a bf16 instantiation (fp32 is 310 GB against a 402 GB `CommitLimit` here);
* per-tensor weight copy (a whole `state_dict`, even with `assign=True`, is
  OOM-killed on this box).

### Bugs found and fixed during the build (each was caught by a test or a probe)

| bug | how it surfaced | fix |
|---|---|---|
| `kv_b` head layout | fluent-but-wrong decode | the converter splits `kv_b` into per-head `[nope|value]` blocks |
| q stride on the transposed qk projection | fluent-but-wrong decode (every head after the first read the wrong lanes) | pass the **full** `qk_head` stride, not the nope count |
| `ScratchBytes` under-counted three 4-byte slots | SIGSEGV inside `libcuda` on a `DtoH` copy, one stage later | one `add()` per `Take()`, plus an arena-overflow assertion that **names** the mismatch |
| dense FFN sized into the MoE scratch | 27k-element write into a 3k-element buffer | separate `d_gu`/`d_act` buffers |
| expert device slots double-booked | `out of memory` at layer 0/3 | the slots are a second allocation sized from the VRAM left after the arena |
| `WarpSum` used as a block reduction | RMSNorm/router/sink scores normalized by one warp's partial sum | `BlockSum` with a shared-memory broadcast |
| grid-wide dependency in `ihc_mix` | every block read block 0's rsqrt with no grid sync | each block recomputes the 384-element norm |
| indexer sigmoid-vs-softmax pooling, `ape` on the wrong operand | found reading the reference | gate the pooling with a softmax over the group; `ape` joins the gate logits |
| tokenizer: prefix-fail aborted the alternation | `" _call"` and `"   m"` split per character | fall through to the next alternative; bound the main pattern at the stage gap |
| escape strip width for `<｜…｜>` | malformed UTF-8 in the escaped form | strip 4 bytes per edge (ASCII `<` + 3-byte U+FF5C) |
