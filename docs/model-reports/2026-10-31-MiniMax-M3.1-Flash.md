**Verdict at a glance:** MiniMax-M3.1-Flash is a **sibling of MiniMax-M3**, not
a new architecture: the 428B/23B-active sparse-MoE decoder keeps the same
geometry and gains two checkpoint-level changes — MiniMax Sparse Attention on
every layer and RoPE theta 1e7 — plus a pre-quantized release (MXFP8 dense,
NVFP4 experts) and a revised chat template with fixed adaptive thinking. The

passes every parity gate we have on the real weights: SelfCheck ×3 bit-exact,
FSI 3/3, CODE 3/3, DET 3/3, and a real tool round-trip.

## Publish-ready post

### MiniMax-M3.1-Flash, running locally in a C++/CUDA engine

We ported MiniMax's M3.1-Flash — a 428-billion-parameter mixture-of-experts
model with ~23 billion active parameters — into our own Blackwell inference
engine. It is the second member of the MiniMax family we run: M3.1 shares M3's
decoder geometry, so the work was to absorb what the new checkpoint changes,
not to write a new architecture.

Two changes matter for an inference engine. First, MiniMax Sparse Attention now
runs on **every** layer (M3 kept the first three layers dense), so the
Lightning-Indexer block selection is always live; our kernel already handled it
and the switch is entirely data-driven. Second, the release is
**quantization-aware-trained and shipped pre-quantized**: the dense
projections are MXFP8 (FP8 payload with one shared exponent per 32 columns) and
the routed experts are already NVIDIA NVFP4. The converter dequantizes the
dense side once and re-quantizes it to our uniform NVFP4 format, and copies the
expert records through verbatim — the expert bytes on disk are the bytes the
kernel reads, with no requantization pass.

The 236 GB release becomes a 227 GB tree. On a single 32 GB RTX 5090 the dense
graph is pinned in 10.5 GiB and the routed-expert set streams from disk through
an LRU of device slots. The model answers the canonical fact check correctly
and deterministically ("The capital of France is Paris."), passes our three
structured-answer parity suites, and calls tools with the checkpoint's native
XML format.

#### What the checkpoint forced into the engine

1. **Sparse attention on all 60 layers.** The indexer weights exist on layers
   0-2 (they did not in M3), and its key history must be cached on those layers
   too. The loader is now dispatch-driven and each model member cross-checks
   the dispatch arrays against its own frozen passport, so an M3 tree and an
   M3.1 tree cannot be loaded as each other.
2. **RoPE theta 1e7** (M3: 5e6), including the indexer's RoPE. The same
   passport check pins it.
3. **A pre-quantized source.** Dense projections arrive as FP8 with a
   per-32-column power-of-two exponent; routed experts arrive as NVFP4 with a
   per-16 FP8 block scale and a per-tensor divisor. The converter feeds the
   dense pair to the engine's existing MXFP8-aware quantizer and inverts the
   expert divisor to our multiply convention — the same rule we already used for
   another vendor's NVFP4 release.
4. **Fixed adaptive thinking.** The new chat template removes the thinking-mode
   switch: the model decides for itself whether to reason, and the generation
   prompt no longer carries the "answer directly" marker. In practice the model
   opens a short `<mm:think>` block and then answers; a parity probe that only
   looks at the first handful of tokens would miss the answer, so the check
   window is adapted.
5. **A new system prompt and role mapping.** The default system message names
   the model version and appends an opaque `<model_id>` line, mid-conversation
   system turns render as `developer`, and consecutive tool results share one
   message block. All three are reproduced by a per-checkpoint render policy, so
   the M3 template remains untouched.
6. **Same vocabulary.** The tokenizer files are byte-identical to M3's, so the
   already-verified pre-tokenizer policy transfers unchanged.

#### Measured

- SelfCheck: "The capital of France is" → "Paris", bit-exact across three
  stress cycles (`logits_hash 2daad7a5ba024549`).
- FSI 3/3, CODE 3/3, DET 3/3 (three byte-identical runs per DET prompt).
- Native tool round-trip on real weights: `get_weather {"city": "Paris"}`.
- **6.23 t/s (max-speed) / 6.18 t/s (strict bit-exact)** at 2 048 generated
  tokens; TTFT 48.8 s / 49.2 s; 152 W average, 186 W peak; 10.5 GiB pinned.
- Conversion: 236 GB → 227 GB in ~6 minutes; 523 vision-tower/projector tensors
  and a separate 2.2 GB speculative draft head are stored and counted, not
  applied.

#### Limits

The vision tower and the DSpark speculative draft head are not implemented in
this engine — this release runs the text decoder only, and speculative decoding
is not part of the pipeline. The parity goldens are derived from the prompts'
Expected Templates rather than from a running source model: the 428B
quantization-aware checkpoint has no single-GPU execution path here, so the
goldens guard the converted path (tokenizer, template, answer extraction) and
not bitwise source parity. As with M3, the routed-expert set is streamed per
token, which is what sets the ~6 t/s decode rate.

## Internal evidence

### Stage 0 triage

Source inventory (`model.safetensors.index.json`, 89 632 tensors):

- text: `language_model.model.layers.N.*` + root `language_model.lm_head.weight`
  and `language_model.model.norm.weight`;
- dense projections: `<proj>.weight` (F8_E4M3) + `<proj>.weight_scale_inv`
  (U8, `[rows, cols/32]`, E8M0 exponent; dequant = payload × 2^(u−127);
  validated: q_proj dequantized std 0.0305);
- routed experts: `w{1,2,3}.weight_packed` (U8, `[rows, cols/2]`),
  `weight_scale` (F8_E4M3, `[rows, cols/16]`), `weight_global_scale` (F32,
  divisor), `input_global_scale` (activation, unused);
- router: `block_sparse_moe.gate.weight` F32 + `e_score_correction_bias` F32;
- norms: BF16 (Gemma offset form); embed/head BF16;
- ballast: 523 `vision_tower.*` / `multi_modal_projector.*` /
  `patch_merge_mlp.*` tensors, counted; the 2.2 GB `dspark/` draft head is
  outside the root weight map.

Config deltas vs M3 (both verified in `config.json`): `rope_theta` 1e7 vs 5e6;
`sparse_attention_freq` all ones vs `[0,0,0,1…]`; no MTP fields; source
`quantization_config` present (`mxfp8` dense + `NVFP4` experts).

### Declared debt

- FSI/CODE/DET goldens are **template-derived**, not source-captured: the
  source is a 428B QAT release with no single-card runner. The converted path
  is guarded on the checkpoint's own tokenizer and chat template; source
  bit-parity is not claimed.
- No speculative decoding: the shipped DSpark draft head is stored and counted
  only.
- Vision/multimodal input is out of scope (tower stripped).
- The streamed-expert t/s is a function of the generated continuation (expert
  cache hit rate); the row is seeded at the canonical prompt, exactly like M3.

### Artifact notes for the model authors

- `text_config` does not carry `num_mtp_modules` (M3 did, unpopulated); the
  draft head moved to a sibling `dspark/` directory with its own config and
  weight map, which is easy to miss when a loader only scans the root shards.
- `pad_token_id` is not declared in `config.json` or `generation_config.json`;
  only bos/eos are. The engine derives its pad row from the tokenizer
  configuration.
- `sparse_disable_index_value` is all ones while `sparse_attention_freq` is
  also all ones; the two are redundant in this release. The converter derives
  the sparse boundary from the frequency array and rejects a non-prefix
  pattern.
