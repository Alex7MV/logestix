## Publish-ready post

### GigaChat3.5 432B on one RTX 5090

We ported Sber's GigaChat3.5-432B-A28B-Reasoning into our Blackwell inference
engine. It is not a transformer in the usual sense: 30 of its 40 layers use
GatedDeltaNet (a gated delta-rule linear attention with a causal depthwise
conv), 10 use a gated MLA with a 512-dim KV latent, and every layer carries a
256-expert mixture-of-experts with 8 active experts. Every normalization in the
model is a `ZeroCenteredGatedNorm` — an RMSNorm whose scale is `1+w`, followed
by a rank-16 SiLU gate fed into a sigmoid that scales the normalized hidden
state.

The 416 GB FP8 checkpoint converts to a 241 GB NVFP4 tree: dense weights stay
on the card (26.2 GiB, including the auto-sized expert slot cache) and the 219 GB of
routed experts live in a pinned host store, fetched per token through an LRU.
It decodes at **11.3 tokens/s** at 2 048 generated tokens — for a 432B model on
a 32 GB consumer card, that is a working research and evaluation target, not a
production server.

#### What the checkpoint forced into the engine

1. **ZeroCenteredGatedNorm on every norm.** The weight is centred on zero
   (`1+w`) and a rank-16 up/down gate applies `silu` then `sigmoid`, scaling
   the *normalized* output by `2·sigmoid(silu(h))`. Reading the weights as plain
   scales zeroes the activations.
2. **Two attention mechanisms in one stack.** Full-attention layers run a gated
   MLA (q-lora 1536, kv-lora 512, qk 128+64 interleaved-YaRN RoPE, an output
   gate applied before `o_proj`); the other 30 run GatedDeltaNet with a 4-tap
   causal conv, per-head `A_log`/`dt_bias`, and a zero-centred sigmoid-gated
   output norm. The layer map comes from `config.full_attention_layers`
   (3, 7, …, 39).
3. **Scale conventions differ from the DeepSeek family.** MLA scaling is
   `sqrt(7168/1536)` / `sqrt(7168/512)` applied to the *latents* before the
   up-projections; the attention softmax scale is `192^-0.5 · mscale^2` with
   YaRN factor 8 over a 32k window; SwiGLU clamps gate at +10 and up at ±10;
   the router is sigmoid + correction bias, renormalized, then × 2.5.
4. **The tokenizer needed its own policy.** The checkpoint is the
   Llama-3/o200k byte-level BPE with the 7-alternative case-run pre-tokenizer
   (contraction suffix, `\p{N}{1,3}`, no CJK isolation). The engine's default
   legacy split mis-splits mixed-case identifiers, so the converter now builds
   the arrows with `tokenizer_kind 3` and a 30-case parity golden captured
   from the checkpoint's own tokenizer (30/30 exact).
5. **MTP is structural only.** Three next-token-prediction layers (144 tensors,
   13 GB) are converted, stored and counted, never loaded resident and never
   applied.
6. **FP8 block-128 with a partial tile.** `kv_a_proj_with_mqa` is `[576,7168]`
   — 4·128 + 64 rows — so the dequant kernel clamps the last tile instead of
   reading past it.

#### Measured

- SelfCheck: "The capital of France is" → **"Paris"** (token 19904), three
  cycles with identical `final_logits` (`logits_hash 2743ee1c26f859d5`).
- Native tool round-trip (real weights): the model emits the chatml-v5 GCML
  `<｜GCML｜tool_calls>` body and the parser returns
  `get_weather {"city":"Paris"}`.
- FSI 3/3, CODE 3/3, DET 3/3 (DET deterministic across 3 runs per prompt).
- **11.32 t/s** (perf) / **11.10 t/s** (strict bit-exact `r3`) at 2 048
  tokens, TTFT 3.90 / 3.97 s, 189 / 192 W, 26.2 GiB resident.
- Tokenizer parity 30/30 against the checkpoint's own `tokenizer.json`.

#### Limits

- The three QA goldens are **template-derived**: the published reference is
  the vendor's multi-GPU FP8 stack with a custom `GigaChat35ForCausalLM`, there
  is no single-GPU path, and the 864 GB BF16 body exceeds this host's 750 GB
  of RAM. They pin the converted path against the prompt's Expected Template,
  not against a source run — recorded as a provenance field in each golden,
  not as source parity.
- 4 096-token session ceiling (`max_seq_`); the 262k context in `config.json`
  would need ~34 GiB of KV alone.
- Decode is bound by expert H2D: ~3.7 GB/token of routed weights at the PCIe
  Gen5 ceiling, with the cache hit rate set by free VRAM. The audit in
  `docs/GIGACHAT_SPEED_AUDIT.md` records the attribution and the ceiling.

### Conversion

```
lsxforge --gigachat --input <vault>/GigaChat3.5-432B-A28B-Reasoning \
                       --output <vault>/GigaChat3.5-432B-A28B-Reasoning
```
Result: 40 layers, 9472 experts, 144 MTP tensors stored, 1009 pinned tensors,
241 GB (219 GB experts / 13 GB MTP / 9.7 GB pinned), index
`"tokenizer": "arrow-bpe"`. The converter now builds and verifies the tokenizer
arrows inside the same run (`tokenizer_kind 3`). The conversion was executed
twice — once before and once after the tokenizer stage landed — and both trees
produce the same SelfCheck hash, so the stage is numerically inert and the
shipped tree is exactly the converter's output.

### Golden provenance

All three goldens carry
`source: "prompt-template (source not runnable locally: 432B FP8-block-128
vendor stack (multi-GPU reference); no single-GPU path and the BF16 body
(864 GB) exceeds host RAM)"`, `raw: ""`, and `max_new_tokens: 1536` (the
reasoning trace of FSI-02 needs more than 512). `Det` additionally carries
`stress_runs: 3`.

### Numeric class

The default path is `kAuto`; `r3` (`FastMathMode::kOff`) measures 11.10 t/s,
i.e. the model is memory-bound enough that the strict class costs ~2%.
SelfCheck is bit-exact at both.

### Host resources

During the perf run: peak host RSS ~466 GB (pinned expert store 219 GB + the
mapped views), 99% GPU utilisation, 187 W average. The store pins in
14 × 16 GiB chunks in ~7.2 s on a warm page cache.

Resident footprint measured with `lsxbenchmark --bench --max-gen 16`:
**26 783 MiB** (dense graph + auto-sized expert slot cache).
