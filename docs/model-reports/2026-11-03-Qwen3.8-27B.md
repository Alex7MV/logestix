## Publish-ready post

### Notes from an independent NVFP4 port of Qwen3.8-27B

We run Qwen3.8-27B in our own C++/CUDA inference engine (no PyTorch at runtime)
and converted the BF16 release in place to NVFP4: 51 GiB of safetensors → a
15 GB tree, entirely device-resident at 14.1 GiB on a single RTX 5090, loaded in
about a second. The text model is a hybrid: 64 layers in 16 repeating blocks of
three GatedDeltaNet (linear-attention) layers followed by one gated-attention
layer, with a 24/4-head, 256-dim attention head that rotates 64 dimensions.

#### What worked well

- **Greedy determinism is solid.** The control prompt "The capital of France is"
  answers "Paris" and three independent runs produce byte-identical full-vocabulary
  logits (`logits_hash = 8bf2a2bf937eca91`), including across a full model reload.
  Quantising the body — including embeddings and the LM head — to NVFP4 does not
  disturb any of the parity gates we run (a financial-services formula set, a
  compiler-syntactic code set, and a determinism/near-tie set; 3/3 on each).
- **The native tool wire is unambiguous.** The template's
  `<tool_call>` / `<function=NAME>` / `<parameter=KEY>` XML is parsed without
  heuristics; a real-weight round-trip produced the `get_weather` call with
  `{"city":"Paris"}` after 26 tokens.
- **The tokenizer bridge reproduces the checkpoint exactly** (byte-level BPE,
  248 320 entries, ChatML control markers as their own ids).

#### Six checkpoint facts that are easy to get subtly wrong

1. **The language weights are stored under `model.language_model.*`, not
   `model.*`.** A plain `AutoModelForCausalLM.from_pretrained` on this
   `Qwen3_5ForConditionalGeneration` checkpoint maps to the text class, whose
   parameter names are `model.*`; the load then silently drops every language
   tensor and keeps only the (stripped) vision module. The failure mode is not an
   exception — it is an empty or random model. Any loader must remap
   `model.language_model.` → `model.`. A note on the model card
   ("this is a conditional-generation checkpoint; use the text sub-model") would
   save integrators the debugging pass.

2. **MTP lives at the root (`mtp.*`), not under `model.language_model.`.** The
   checkpoint ships one multi-token-prediction layer (15 tensors). A stripper
   that filters the language prefix alone will miss it and either fail a strict
   coverage check or carry weights that are never used; ours strips and counts it.

3. **`layer_types` is not uniform.** The config encodes the hybrid as
   `full_attention_interval = 4`, and the exact layer list is in `layer_types`
   (linear, linear, linear, full, …). Reading "full attention every N" and
   assuming an offset — or treating the model as a plain GQA decoder — silently
   decodes garbage. The GDN-side geometry is separate and easy to mix up:
   48 value heads / 16 key heads at 128 dims, depthwise conv with kernel 4.

4. **The "mRoPE" config block is for the vision path.** `rope_parameters`
   carries `mrope_interleaved: true` and `mrope_section: [11, 11, 10]`, while the
   attention head rotates only `head_dim × 0.25 = 64` of its 256 dims at
   θ = 1e7. For text-only input the three mRoPE position streams are identical,
   so the text path is plain partial RoPE on 64 dims; applying the interleaved
   multimodal rotation as if it were the text rotation changes the angles and is
   a silent correctness bug that only shows up as worse answers, never as an
   error.

5. **Thinking is on by default.** The chat template's default branch emits
   `<|im_start|>assistant\n<think>\n` and prepends a reasoning-effort instruction
   (`xhigh` by default, with `medium`/`low` selectable). Only
   `enable_thinking = false` produces the pre-closed `<think>\n\n</think>\n\n`
   prefill that a deterministic, non-reasoning serving path wants. Our bridge
   emits exactly the `enable_thinking = false` form, including the tool-system
   block byte-for-byte.

6. **The stop set is a list, and padding collides with it.**
   `generation_config.json` declares `eos_token_id: [248046, 248044]` and
   `pad_token_id: 248044`; `tokenizer_config.json` names `<|im_end|>` (248046) as
   the EOS and `<|endoftext|>` (248044) as padding. The turns end on
   `<|im_end|>`, which is why single-stop generation is correct here — but an
   integrator who takes the *first* entry of the list, or who treats pad as EOS,
   can stop in the wrong place. `pad_token_id` is also `null` in
   `text_config`, so the value only exists at the top level.

#### Measured

Three gates are captured from the source weights and compared at the greedy
first-answer boundary; a fourth repeats each prompt three times and requires
byte-identical token streams.

| | result |
|---|---|
| SelfCheck ("Paris") | PASS ×3, bit-identical logits, `logits_hash = 8bf2a2bf937eca91` |
| Financial-services formula set | 3/3 |
| Compiler-syntactic code set | 3/3 |
| Determinism / near-tie set | 3/3, `deterministic = true` on all three |
| Native tool round-trip | `get_weather {"city":"Paris"}`, 26 tokens |
| Decode throughput, 2 048 tokens | 56.31 t/s (auto), 60.15 t/s (strict); TTFT 92.9 / 78.6 ms |
| Residency | 14.1 GiB weights, ~1.1 s load, 472–503 W average during decode |

#### What we did not run

- **Vision and video are out of scope.** The 333-tensor vision tower is stripped
  and counted; the `image_token_id`/`video_token_id`/`<|vision_start|>` entries
  remain in the vocabulary but no image path exists.
- **MTP/speculative decoding is not applied** — the layer is stored (counted)
  but never executed.
- **Long context is bounded by memory, not by the model.** The native window is
  262 144 tokens; at 4 KV heads × 256 dims × 16 full-attention layers that is
  ≈16 GiB of BF16 K/V, so the conversion-time profile already reports 32 GiB
  "optimal" (weights + KV + workspace). We verified short and medium prompt
  framing, not the full native window, and not the vendor's 1M-token extension.

Overall: a well-specified checkpoint to port. The only thing that cost real time
was the `model.language_model.*` storage prefix; the rest is documented above so
the next integrator does not rediscover it.

### Architecture as implemented

- 64 layers = 16 × (3 × GatedDeltaNet → FFN, then 1 × gated attention → FFN);
  `full_attention_interval = 4`, full-attention layers at indices 3, 7, …, 63.
- GatedDeltaNet: 48 value heads / 16 key heads × 128 dims, depthwise
  `conv1d` with kernel 4, `A_log` / `dt_bias` / `in_proj_z` / output norm.
- Gated attention: 24 Q / 4 KV heads at `head_dim = 256` (GQA ratio 6),
  per-head q/k RMSNorm, swish output gate applied before `o_proj`, partial RoPE
  on 64 of 256 dims at θ = 1e7.
- Dense SwiGLU FFN, `intermediate_size = 17 408`; `hidden_size = 5 120`;
  `vocab_size = 248 320`; `tie_word_embeddings = false`; `rms_norm_eps = 1e-6`.
- Stripped and counted: 333 `model.visual.*` tensors (vision tower) and 15
  `mtp.*` tensors (one multi-token-prediction layer).
- Quantisation: NVFP4 for every dense linear, embeddings and the LM head
  (2 nibbles/byte + E4M3 block scales + a per-tensor global scale); norms, the
  GDN conv, `A_log`, `dt_bias` and `linear_attn.norm` stay raw; `gate_proj` and
  `up_proj` are fused into a single `[2I, H]` record with a shared global scale.
