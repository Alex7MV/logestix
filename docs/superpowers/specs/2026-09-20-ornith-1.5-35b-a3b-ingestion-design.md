# Ornith-1.5-35B-A3B Ingestion Design

Date: 2026-09-20
Status: Implemented (2026-09-21)
Goal: Adapt `Ornith-1.5-35B-A3B` (an MLX-exported, architecture-identical
Qwen3.5-MoE reasoning fine-tune) into logestix per the Model Ingestion Protocol
(8 stages), as its own model family, implemented via TDD on the
`feat/ornith-1.5-35b-a3b-ingestion` branch.

## Reconnaissance (2026-09-20)

Source: `/mnt/llm_models/models/Ornith-1.5-35B-A3B-MLX` — 65 GB, BF16, 14 shards
(`model-00001-of-00014.safetensors`), a full tokenizer (`tokenizer.json`,
`tokenizer_config.json`), no vision/audio/MTP weights present.

- `architectures = Qwen3_5MoeForConditionalGeneration`, `model_type = qwen3_5_moe` —
  architecturally identical to Qwen3.5-35B-A3B / Qwen3.6-35B-A3B.
- Text geometry matches 3.5/3.6 exactly: hidden=2048, 40 layers (GDN hybrid,
  full attention every 4th: `i%4==3`), heads=16, kv_heads=2, head_dim=256,
  linear 16/32/128/128, conv_kernel=4, vocab=248320, E=256, top-8,
  moe_intermediate=512, shared_intermediate=512, rms_eps=1e-6,
  partial_rotary_factor=0.25, rope_theta=1e7.
- The checkpoint is exported in **MLX tensor layout**, not the HF layout the
  existing `qwen_moe` converter expects:
  - prefix `language_model.model.` (HF: `model.language_model.`);
    `language_model.lm_head.weight` (HF: `lm_head.weight`).
  - experts are three stacked tensors
    `mlp.switch_mlp.{gate_proj,up_proj,down_proj}.weight`
    `[256,512,2048] / [256,512,2048] / [256,2048,512]`
    (HF: fused `mlp.experts.gate_up_proj [256,1024,2048]` +
    `mlp.experts.down_proj [256,2048,512]`).
  - `linear_attn.conv1d.weight` shape `[8192,4,1]` (HF: `[8192,1,4]`); the
    flattening is byte-identical (`c*K+k`), only the shape metadata differs.
  - All other tensor names/shapes are identical to the HF layout
    (`self_attn.*`, `linear_attn.*`, `mlp.gate.weight`, `mlp.shared_expert.*`,
    `mlp.shared_expert_gate.weight`, `input/post_attention_layernorm`,
    `model.norm.weight`).
  - No `mtp.*` and no `visual.*` tensors (text-only export).
- Config delta vs Qwen3.6: top-level `bos_token_id = null` but
  `text_config.bos_token_id = 248044`; `eos_token_id = [248046, 248044]`;
  `router_aux_loss_coef = 0.0`; `use_cache = false`; no `vision_config`.
- Tokenizer: `tokenizer_class = Qwen2Tokenizer`, vocab 248320; `bos_token = null`,
  `eos_token = <|im_end|>`, `pad_token = <|endoftext|>`.
- The model is documented as a reasoning model (default assistant turn opens a
  `<think>` block), built on Qwen3.5/Gemma4 with continued pretraining and RL.

## Operator decisions

| Question | Decision |
|---|---|
| Family classification | **New family `ornith`** (own files, namespace, guards), not a qwen variant |
| Converter | **Standalone** converter `ornith_moe_convert.cpp` (own MLX classifier + body); `qwen_moe_convert.cpp` is not modified |
| Runtime | **Duplicate the MoE family layer** (`ornith_moe_{constants,load,inference,model}`); the generic `qwen_inference.*` kernel layer is treated as shared (option 1b) |
| Kernel call policy | Ornith's copied inference routes NVFP4 through `lsx_nvfp4::RunLsxNvfp4Gemm` / `lsx_nvfp4::LsxTcFastMath` directly, never through the `qwen::` aliases |
| Step 7 (network passport.bin) | Skip (same deviation as Qwen3.5/3.6 — the shared bridge is owned by the GLM-5.3-Flash↔DeepSeek-V4-Flash bridge); recorded here |
| Validation scope | Full ingest with real conversion, SelfCheck Paris and a perf baseline |

## Invariant #1: Model autonomy

- Its own frozen passport: `ornith_moe_constants.h`, namespace
  `lsxcommon::ornith::frozen` (leaf header, no cross-includes of other
  passports — independence guard).
- Its own `kType = "ornith-1.5-35b-a3b"`, its own `ValidateGeometry`, its own
  `Infer` opening `LsxFastMathScope(EffectiveFastMathMode(cfg_))` (the
  independence-guard consumer list).
- The qwen model files are not modified by this ingestion. The only shared
  dependency is the generic kernel layer (`qwen_inference.*`,
  `qwen_inference_load.*`), which the repo already documents as shared by
  dense+MoE (`AllowedCommon` in `test_code_naming_guard`).
- Legitimate one-line touches of existing files: `model_registry.cpp`,
  `apps/lsxforge/src/main.cpp`, `libs/lsxcommon/CMakeLists.txt`,
  `tests/CMakeLists.txt`, the four guard registries, `AGENTS.md`,

## Converter

- Self-contained: does **not** include or modify `qwen_moe_convert.*`.
- Classifier accepts directly the MLX names and maps them to the same output
  kinds the runtime expects.
- Expert handling: `switch_mlp.gate_proj` → w1, `switch_mlp.up_proj` → w3,
  `switch_mlp.down_proj` → w2; one `experts/layer_<l>/exp_<e>.arrow` per expert
  via `PackedExpert` + `ExpertSchema::MakeBatch`.
- `linear_attn.conv1d.weight` stored raw with normalized shape `{C,1,K}` and the
  same bytes.
- Quantization policy unchanged from the protocol: NVFP4 for embed/lm_head/
  attention/linear-attn/shared-expert/routed-expert matrices; raw high precision
  for norms, router `mlp.gate.weight`, `shared_expert_gate`, `conv1d`, `A_log`,
  `dt_bias`.
- Tokenizer: `integrity::BuildAndVerifyTokenizer` with `bos_required=false`,
  `eos_required=true`.
- Index manifest byte-compatible with the runtime parser (`ParseOrnithMoeIndex`):
  `format`, `model`, geometry fields, `layer_types`, `num_experts*`,
  `eos_token_id`, `bos_token_id=248044`, `skipped_visual_tensors`,
  `tokenizer`, `total_pinned_tensors`.
- `OrnithMoeTopology` is defined in `ornith_moe_convert.h` (own type; no
  cross-family topology reuse).

## Model class

- `OrnithMoeModelBase : ModelBase` (copied/renamed from `QwenMoeModelBase`):
  owns `OrnithMoePinnedWeights`, `OrnithMoeExpertStore`, device cache,
  generation scratch, `qwen::QwenKvCache` session tail.
- `OrnithMoeModel final : OrnithMoeModelBase`:
  - `kType = "ornith-1.5-35b-a3b"`;
  - ctor mirrors the qwen TC toggle policy through `lsx_nvfp4` directly;
  - `Load()`: dense load, expert store, governor, cache sizing/prestaging;
  - `Infer()`: `LsxFastMathScope(EffectiveFastMathMode(cfg_))` →
    `RunInferShared` (session policy + `RunOrnithMoeGeneration`);
  - `SelfCheck()`: Paris control (`"The capital of France is"` → `"Paris"`)
    via the shared runtime helper;
  - `ValidateGeometry()`: against `ornith::frozen` (+ synthetic escape hatch).

## Metadata / vault

Converted artifacts under the unified `<output_root>/logestix/` layout
(`pinned/`, `router/`, `shared/`, `experts/`, optional `mtp/`,
`model.index.json`), written directly from the `--output` root exactly like the
qwen converters (no `lsx_model_metadata` path authority in the converter).
Format tag `logestix-ornithmoe`, `"model": "Ornith-1.5-35B-A3B"` →
`detect_model_type` normalizes to `ornith-1.5-35b-a3b`.

## Risks

- **SelfCheck control prompt**: Ornith is a reasoning fine-tune; the raw
  continuation `"The capital of France is"` may top-1 `<think>` rather than
  `"Paris"`. Mitigation: try the raw protocol first (Qwen3.5/3.6 parity); if it
  fails, frame the SelfCheck with the checkpoint's own chat template and pin the
  framing in the selfcheck test (recorded as a protocol deviation).
- **MLX conv/expert layout**: verified byte-identical flattening; pinned by a
  converter test comparing against expected per-expert payload sizes and the
  normalized conv shape.
- **Duplication drift**: the copied MoE files carry a header comment naming the
  qwen source version they were adapted from; future qwen fixes must be ported.
- **`--model`/detect path**: the vault directory is `Ornith-1.5-35B-A3B-MLX`
  while the `kType` is derived from the index `model` field; the tests assert
  the normalization `Ornith-1.5-35B-A3B` → `ornith-1.5-35b-a3b`.
- **Windows test restriction** (`ctest -R "qwen|gemma"`) does not match the new
  `ornith` prefix; if the Windows restriction list needs ornith coverage it is
  added explicitly.

## Implementation notes (2026-09-21)

Two findings surfaced during the real-model run and were fixed in `1b69c6b`:

1. **MLX plain-RMSNorm offset form.** The MLX export stores the plain RMSNorm
   weights (`input_layernorm`, `post_attention_layernorm`, `q_norm`, `k_norm`,
   the final `norm`) in **absolute form** (true multiplier `w`, ≈1.x), whereas
   the HF model / runtime use the **offset form** `out = rmsnorm(x) * (1 + w)`
   (stored `w ≈ true-1`). Fed raw, the offset norms (≈1.x) were interpreted as
   `1 + w` (≈2.x), scrambling every layer. `RMSNormGated`
   (`linear_attn.norm.weight`) is absolute in both exporters and is left
   untouched. The converter now subtracts 1.0 for the five plain-norm kinds and
   stores them as F32 (`OffsetNormToF32`) to preserve the small offsets; the
   unified layout and the shared loader are unchanged. Diagnosed by diffing
   Ornith against the Qwen3.6-35B-A3B checkpoint: every other tensor matched a
   close fine-tune delta, only the plain norms differed by exactly +1.0.
2. **Reasoning-model SelfCheck.** Ornith is a reasoning fine-tune: neither the
   raw control prompt nor the native thinking mode answers `"Paris"` as the
   first token. `OrnithMoeModel::SelfCheck` now frames the control prompt with
   the checkpoint's own ChatML template (prefilled empty `<think>...</think>`,
   the template's `enable_thinking=false` path) via
   `OrnithMoeModel::BuildPromptInputIds`, and uses `ParisSelfCheckOptions`
   `{frame_prompt=true, min_tokens=16, answer_window=16, substring_match=true}`.
   The model then emits `"The capital of France is **Paris**."`; the canonical
   answer appears within the window and `selfcheck_passed == true`. This is a
   recorded per-model deviation from the strict first-token equality contract.

Measured: conversion of the real checkpoint 4 min; SelfCheck 3 bit-exact
cycles green; perf baseline `141.85 tok/s` (mode `perf`, 2048 tokens, RTX 5090).

## Adaptation: the transformers (HF) re-export (2026-10-07)

Branch `feat/ornith-hf-export-adaptation`. The upstream release replaced the
MLX export with a **transformers** re-export of the same fine-tune, so the
ingestion had to be adapted rather than re-done. Stage 0 triage of the new
source (`/mnt/llm_models/models/Ornith-1.5-35B-A3B`, 16 shards, 65 GiB BF16):

| Field | New HF export | Delta vs the MLX export |
|---|---|---|
| prefix | `model.language_model.*` | `language_model.model.*` |
| lm head | `lm_head.weight` (root) | `language_model.lm_head.weight` |
| experts | fused `mlp.experts.gate_up_proj [256,1024,2048]` + `mlp.experts.down_proj [256,2048,512]` | three stacked `mlp.switch_mlp.*` tensors |
| conv1d | `linear_attn.conv1d.weight [8192,1,4]` | `[8192,4,1]` (byte-identical flat order) |
| plain norms | **offset** form (`input_layernorm` mean 0.031, final `norm` mean 1.640) | absolute form (mean ≈ 1.0) |
| ballast | `model.visual.*` — 27 ViT blocks, 1 patch-embed and the merger tensors (**333 tensors**, skipped + counted) | absent |
| ballast | `mtp.*` — 1 speculative layer (attention + 256 routed experts + shared expert + norms, **785 tensors**, converted, stored, counted) | absent |
| config | `vision_config` present, `mtp_num_hidden_layers: 1`, `rope_parameters` with `mrope_interleaved`, `mrope_section [11,11,10]` | text-only export |

Unchanged, so nothing in the runtime layer moved: the text geometry (hidden
2048, 40 layers with `i%4==3` full attention, 16/2 heads, head_dim 256,
linear 16/32/128/128, conv 4, vocab 248320, E=256 top-8, moe/shared
intermediate 512, rms_eps 1e-6, partial_rotary 0.25, rope_theta 1e7,
bos 248044) and the tokenizer (Qwen2Tokenizer BPE, 248044 base pieces +
26 added tokens). `mrope_section` sums to 32 = the 64 rotary dimensions of
`partial_rotary_factor 0.25`, and for text-only prompts all three MRoPE
sections share one position — MRoPE therefore degenerates to the plain RoPE
the runtime already applies, which the SelfCheck/FSI/CODE/DET results confirm.

`chat_template.jinja` renders the turns as plain role words
(`system\n…`, `# Tools` + `<tools>`, `user\n…`, `assistant\n<think>\n`,
`<tool_response>`, and the `<tool_call>\n<function=…>\n<parameter=…>`
codec). The repo's `RenderQwenConversation` / `ParseQwenTokenCalls` implement
the same turn structure with the Qwen control markers
(`<|im_start|>`/`<|im_end|>`, both present as added tokens 248045/248046)
instead of bare role words; the tool body format is byte-identical. This
ChatML rendering is a deliberate carry-over from the MLX-era ingestion (the
checkpoint is the same fine-tune) and is verified end to end: the markers
`<tool_call>`/`</tool_call>` (248058/248059), `<tool_response>` (248066) and
`<think>`/`</think>` (248068/248069) are plain (`special:false`) added tokens,
every real-weight parity gate below passes at `kOff`, and the real-weight tool
round-trip in `test_ornith_moe_selfcheck.cpp` returns the expected
`get_weather`/`Paris` call. Stage 4b therefore keeps its verdict
(`RenderQwenConversation` + `ParseQwenTokenCalls`, proved by
`test_qwen_tool_framing` and that round-trip). A faithful role-word rendering
is a possible follow-up, not a correctness requirement.

Converter change: `classify_ornith_moe_tensor` now reports the source layout
(`OrnithMoeSourceLayout`) alongside the kind, so the plain-norm fixup is
applied per layout (`ornith_plain_norm_is_absolute` — MLX subtracts 1.0 and
stores F32, HF passes the offset form through as BF16), and both expert
encodings feed the same per-expert NVFP4 files. The MTP subtree is counted in
a new `"deferred": {"mtp": "stored", "mtp_tensors": N}` index block next to
`skipped_visual_tensors`.

All five vault-path references to the retired `Ornith-1.5-35B-A3B-MLX`
directory (selfcheck / FSI / CODE / DET / perf) now point at
`Ornith-1.5-35B-A3B`.
