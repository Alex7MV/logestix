# Apache Arrow 26.0.0 → 26.0.1: бамп пина, IPC-hardening — дизайн

Дата: 2026-11-03
Ветка: `build/arrow-26.0.1` (от `main` @ `60f0bc9d`)
Статус: дизайн одобрен оператором; реализация — по TDD.

## 1. Задача

Перевести FetchContent-пин Apache Arrow с 26.0.0 на 26.0.1, доказать, что
численный и формато-читающий слой не сдвинулся, и ответить на вопрос «есть ли
в 26.0.1 новый функционал, применимый к проекту» проверкой, а не
предположением. Ответ — **нет**: 26.0.1 это patch release (24 коммита,
3 ноября 2026), в IPC/IO/CUDA новых возможностей нет. Единственное
изменение, достижимое из нашего кода, — защита IPC-ридера от невалидного
`map`-массива (GH-54936); оно принимается регресс-тестом.

## 2. Что фактически меняется в 26.0.1

`apache-arrow-26.0.1` = `9e5d6978e9acf372cc989aaaf94e863fe8582c90`, 24 коммита
поверх `446167169` (26.0.0). Пересечение с нашим деревом (по diff'у
26.0.0..26.0.1 и release notes `https://arrow.apache.org/release/26.0.1.html`):

| файл | изменение | достигает нас |
|---|---|---|
| `cpp/src/arrow/ipc/reader.cc` | GH-54936: `Visit(MapType)` проверяет `null_count` child/key до `MapArray::ValidateChildData`; невалидный map из IPC → `Status::Invalid` вместо крэша | **да**, через `ReadRecordBatchFromFile` на чужом/битом файле |
| `cpp/cmake_modules/SetupCxxFlags.cmake` | GH-51690: MSVC больше не определяет `__SSE2__` глобально | только Windows-сборка (здесь не проверяема) |
| `cpp/src/arrow/compute/kernels/vector_selection.cc` | GH-51018: segfault `indices_nonzero` на безчанковом `ChunkedArray` | нет: compute-ядра не вызываем |
| `cpp/src/parquet/**`, `gandiva/**` | CDC-chunking, Thrift 0.24, round-precision | нет: Parquet/Gandiva не собираем |
| `cpp/cmake_modules/ThirdpartyToolchain.cmake`, `cpp/thirdparty/versions.txt` | Brotli 1.2.1, Thrift 0.24 для bundled | нет: bundled-набор нашего конфига — uriparser/xsimd, Boost не скачивается |
| CI/пакеты/macOS R | packaging | нет |

**Вывод по новому функционалу:** в списке «New Features and Improvements»
26.0.1 нет ни одного пункта про IPC, `arrow::io`, memory-mapped files или
CUDA; наш Arrow-слой (`arrow::io::`, `arrow::ipc::`, `arrow::cuda::`, базовые
типы) не получает новых API. Это согласуется с аудитом 2026-11-01
(`docs/ARROW_AUDIT_2026-11-01.md` §3b: «Arrow 26.0.0 в нашем узком пути новых
возможностей не добавляет»), который остаётся в силе для 26.0.1.

## 3. Границы

### Входит

- Пин `apache-arrow-26.0.1` в `CMakeLists.txt` + актуализация комментария про
  bundled Boost (проверить `cpp/thirdparty/versions.txt` после fetch).
- Версионный guard `tests/test_core.cpp` → 26.0.1 (`ARROW_VERSION == 26000001`).
- Регресс-тест IPC map-массива в `tests/test_arrow_validation.cpp` (label
  `fast`, host-only).
- Документация и лицензии: `AGENTS.md`, `README.md`, `DEPENDENCIES.md`,
  `THIRD_PARTY_NOTICES`, `CHANGELOG.md`, приписка в `docs/ARROW_AUDIT_2026-11-01.md`,
  версия в шапке skill'а `building-the-project`.
- Верификация на `linux-debug`: полная сборка, `fast`, `convert`, granite
  SelfCheck, `lsxforge --verify` по granite-дереву.

### НЕ входит (осознанно)

- **Windows/MSVC**: хост Linux; изменение `__SSE2__` не проверяемо. Как и в
  бампе 26.0.0, это фиксируется как «не проверено», а не заявляется.
- **Остальные четыре build-каталога** (`linux-release`,
  `linux-release-znver4`, `linux-release-znver4-aocc`, `mm-release`): они
  переконфигурируются и подтянут 26.0.1 при следующем использовании. Наши
  patch-after-fetch блоки от версии Arrow не зависят.
- **Резидуалы аудита S4/S5/S6** (shared-expert encoding contract, routed
  geometry check, полный vault-аудит): это наш формат/тулинг, от версии Arrow
  не зависят.
- **Новые API Arrow**: применять нечего (см. §2); `-Werror` и работа по
  пунктам 4–10 аудита — отдельные задачи.
- Изменения формата на диске, NUMA/аллокаторы, perf-настройки.

## 4. Реализация

### 4.1 TDD-порядок

1. **RED-1 (контракт IPC).** Новый `TEST_CASE` в
   `tests/test_arrow_validation.cpp`: валидный `map<utf8,int32>` батч пишется
   `RecordBatchFileWriter` в temp-файл и читается `ReadRecordBatchFromFile`
   (positive control, `REQUIRE(ok())`); затем тот же батч с child-структурой
   map'а в состоянии `null_count = kUnknownNullCount` и `buffers[0] = nullptr`
   пишется и читается тем же боевым входом — ожидается
   `REQUIRE(status.IsInvalid())`. На 26.0.0 второй `SECTION` падает крэшем
   (чтение уходит в `GetNullCount()` по нулевому битмапу). Крэш и есть RED;
   exit-код и вывод сохраняются как доказательство в сообщении коммита.
2. **RED-2 (версия).** `tests/test_core.cpp` переводится на 26.0.1:
   `STATIC_REQUIRE(ARROW_VERSION == 26000001)`, `ARROW_VERSION_STRING`,
   `build_info.version/version_string`, `version_patch == 1`, имя TEST_CASE.
   Против заголовков 26.0.0 TU не компилируется — RED guard'а.
3. **GREEN.** `GIT_TAG "apache-arrow-26.0.1"`; reconfigure подтягивает тег в
   `_deps/arrow-src`, Arrow пересобирается, оба RED зеленеют.

Один коммит `build:`, потому что оба RED по определению оставляют дерево
некрасным-незелёным (крэш/несобираемый guard); TDD-доказательства — в теле
коммита.

### 4.2 Регресс-тест: устройство

- Конструкция невалидного батча — через публичный API: `MapBuilder` даёт
  валидный `MapArray`, затем копируется `ArrayData` child-структуры с
  подменой `null_count`/validity-буфера; `RecordBatch::Make` → запись
  `arrow::ipc::RecordBatchFileWriter` (валидации на записи нет — проверено по
  `writer.cc` 26.0.0: `WriteRecordBatch` не вызывает `Validate`).
- Чтение — **только** `lsxcommon::ReadRecordBatchFromFile` (mmap + IPC reader):
  это вход всех лоадеров и `lsxforge --verify`, поэтому тест пинит наш
  контракт «битый чужой файл → `Invalid`, никогда SIGSEGV».
- В 26.0.1 ожидаемый путь: `Visit(MapType)` → `child_data[0]->null_count != 0`
  → `Status::Invalid("Map array child array should have no nulls")`.
- Positive control защищает от «починили, запретив всё»: валидный map-файл
  обязан читаться.
- Тест host-only, без GPU и env-переменных; temp-файл удаляется в конце.

### 4.3 Patch-after-fetch блоки

Перепроверяются фактически (как в бампе 26.0.0), а не предполагаются:

| блок | ожидание в 26.0.1 |
|---|---|
| `CMAKE_POLICY_VERSION_MINIMUM 3.5` (наш root `CMakeLists.txt`, для xsimd/uriparser) | механизм от версии Arrow не зависит; критерий — configure проходит без policy-ошибки |
| Boost multiprecision `literals.hpp` (MSVC + C++20) | Boost не скачивается при наших флагах (no-op); версию Boost сверить по `cpp/thirdparty/versions.txt`, комментарий не переписывать, если она та же |
| bundled fmt (в spdlog) | не относится к Arrow; не трогаем |
| abseil crc32 / str_format | не относится к Arrow; не трогаем; полная сборка доказывает, что не сломались |

## 5. Обработка ошибок и риски

| риск | действие |
|---|---|
| shallow `_deps/arrow-src` не подтягивает новый тег | снести `arrow-src` + `arrow-subbuild`, reconfigure (штатный путь, описан в skill `cuda-cmake-build-gotchas`) |

| предупреждения сборки выросли | сверить с baseline 246 строк / 0 наших (бэклог закрыт 2026-11-03); рост в наших файлах — регрессия, чинить в этом же коммите |

## 6. Верификация (linux-debug)

1. `cmake --preset linux-debug && cmake --build --preset linux-debug` — exit 0;
   `warning:` в наших файлах (`libs/`, `apps/`, `tests/`) — 0. Baseline
   26.0.0 — 246 строк, все в vendored-таргетах; после бампа число может
   сдвинуться только там и должно быть объяснено в коммите.
2. `git -C build/linux-debug/_deps/arrow-src describe --tags` →
   `apache-arrow-26.0.1`; guard-тест зелёный.
3. `ctest --preset linux-debug-fast` — **134/134**; `-convert` — **37/37**.
4. `ctest -R test_granite_dense_selfcheck` — Paris ×3, `logits_hash
   c165e80fde6401cf`, top-1 12366.
5. `lsxforge --verify --input /mnt/fast_storage/huggingface/granite-4.2-30b` —
   `problems=0` (бюджет по умолчанию 256 MiB на дерево).
6. Лицензии: до бампа фиксируются `sha256` файлов `NOTICE.txt` и `LICENSE.txt`
   из `_deps/arrow-src` (26.0.0), после бампа сверяются с 26.0.1; diff
   26.0.0..26.0.1 этих файлов не содержит, а состав bundled-компонентов
   нашего конфига не изменился.

## 7. Коммит

Один коммит `build:`; тело — фактически полученные числа прогона, каркас:

```
build: bump Apache Arrow to 26.0.1 (IPC map-array hardening, no new APIs)

Arrow: apache-arrow-26.0.0 -> 26.0.1 (24 commits, patch release).
Чего в 26.0.1 нет: новых API в IPC/io/CUDA (release notes + diff).
RED на 26.0.0: крэш test_arrow_validation и отказ компиляции guard'а
(точные exit-коды/вывод вставляются по факту прогона).
GREEN на 26.0.1: fast 134/134, convert 37/37,
granite logits_hash=c165e80fde6401cf, lsxforge --verify granite problems=0,
предупреждений наших 0.
Не проверено: Windows/MSVC и четыре остальных пресета.
```

Ветка `build/arrow-26.0.1`; мердж в `main` — только по явной команде
оператора, конвенцией репозитория (`--no-ff`, `merge: …`).
