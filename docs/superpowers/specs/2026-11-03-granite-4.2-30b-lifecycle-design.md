# granite-4.2-30b full lifecycle re-verification — design

## Context

`granite-4.2-30b` (IBM, `/mnt/fast_storage/lsx_model/ibm-granite/granite-4.2-30b`) is the
plain dense Granite 4.2 30B checkpoint (`GraniteForCausalLM`,
`model_type="granite"`). The codebase already carries the complete family —
converter, loader, kernels, model, tokenizer bridge and tool codec
(`libs/lsxcommon/granite_dense_*`, `granite_tool_format.*`, `lsxforge --granite`)
— with all four parity stages wired and goldens committed
(`tests/fixtures/{fsi,code,det}/granite-4.2-30b.json`), plus two perf rows
(`test_perf_baseline_granite_4_2_30b`).

What is **not** done on this freshly downloaded checkpoint:

- no converted vault tree (`granite-4.2-30b/logestix/` is absent);
- no stage-9 model report (`docs/model-reports/` has only the *switch* sibling);
- the perf rows are the 2026-09-22 originals (`commit: "-"`, stale);
- `docs/OPEN_TASKS.md` §K still calls `granite-4.2-30b:code` declared debt, but
  the code golden has existed since 2026-10-07 — the narrative is stale.

This work is a **re-verification of the whole lifecycle on real weights**, not a
new architecture. It closes the vault artifact, the report and the stale docs,
and it re-measures the gates and throughput so every claim has current evidence.

## Plan

### 0. Branch
`feat/granite-4.2-30b-lifecycle` off `main`.

### 1. Conversion (protocol stages 1–3)
Release build. Convert in place into the vault:

```
lsxforge --granite \
  /mnt/fast_storage/lsx_model/ibm-granite/granite-4.2-30b \
  /mnt/fast_storage/lsx_model/ibm-granite/granite-4.2-30b/logestix
```

Scratch under `/mnt/fast_storage/tmp`. Verify: format tag `logestix-granite`,
frozen geometry, tokenizer arrow files built, no silent tensor drops (converter
reports skipped/deferred counts), converted tree ≈16–17 GiB.

### 2. Build
Rebuild `linux-release-znver4-aocc` (perf-grade; matches the seeding protocol of
the other rows) and `linux-debug` (debug-only tests). `BUILD_TESTING=ON`.

### 3. Correctness gates (protocol stages 5–6), TDD
Run RED-first, then GREEN, on the real converted tree:

- `test_granite_dense_selfcheck` — Paris ×3, pinned `logits_hash` (currently
  `3d1604aa75c99a1f` for the fixture run).
- `test_granite_dense_fsi_selfcheck`, `_code_selfcheck`, `_det_selfcheck` —
  existing source-captured goldens.
- native tool round-trip `get_weather {"city":"Paris"}` via
  `test_granite_dense_selfcheck` / `test_granite_tool_framing`.
- fast guards: naming, independence, suite, absl, toolchain.

**TDD rule:** a RED gate that reveals a real defect gets a failing regression
test *before* any fix; no fix without RED→GREEN. A SKIP that hides a missing
golden is not accepted — all three goldens exist, so failure means a real gap.

### 4. Perf (protocol stage 4)
Re-seed `perf` and `r3` through the harness at the canonical 2048-token protocol
(prompt `The capital of France is`, RTX 5090, DRAM probe oracle). Replace the
stale 2026-09-22 rows only with harness output; no hand-edited numbers.

### 5. Launch/serve smoke (protocol stage 5 launch)
`lsxfabric --localmodel <vault> --testprompt` (or `--validate`) once, to confirm
the converted tree drives the engine outside the test harness.

### 6. Stage-9 report + docs
- `docs/model-reports/2026-11-03-granite-4.2-30b.md` — publishable post +
  internal evidence (geometry, conversion counts, gate results with hashes,
  perf/r3 rows, resident VRAM).
- Update `docs/OPEN_TASKS.md` §K: `granite-4.2-30b:code` is no longer debt
  (golden present) — correct the stale narrative.
- Update `AGENTS.md` granite entry: record the four-gate result, tool
  round-trip, perf/r3 rows, report link.

## Acceptance criteria

1. Converted tree exists and loads through the engine; geometry matches the
   passport.
2. SelfCheck Paris ×3 bit-exact.
3. FSI/CODE/DET 3/3 each, or a documented, rehearsed defect closed RED→GREEN.
4. Native tool round-trip green.
5. `perf`/`r3` rows re-seeded from the harness with evidence.
6. `ctest -L fast` green (no regressions).
7. Report + docs committed on the branch.

## Risks / mitigations

- **NVFP4 border cases** (a near-tie gate flipping): the sibling switch
  family needed `FastMathMode::kOff`; if a granite gate is borderline, measure
  before changing the numeric class and record the evidence.
- **Stale goldens**: goldens predate this checkpoint download; if a golden fails
  while the source agrees with itself, re-capture from the source oracle
  (`tools/fsi_capture.py` etc.) and record the reasoning, do not silently edit
  the expected value.
- **Long conversion**: ~57 GB source → in-place, streamed; disk has 1.9 T free.
