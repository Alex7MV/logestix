# Qwen3.8-27B Model Integration

## Status: Draft

## Problem

Add support for Qwen3.8-27B, a larger variant of the Qwen3.5 architecture, located at `D:\Programs\huggingface.co\Qwen3.8-27B`. The model shares the same hybrid GatedDeltaNet + Full Attention architecture as the existing Qwen3.5-9B but with larger dimensions (hidden_size=5120, 64 layers, 24 heads, 48 linear value heads, intermediate_size=17408).

The Model Ingestion Protocol (AGENTS.md, step 3) requires new models to use compile-time geometry macros + static_assert, while the existing Qwen3.5-9B reads geometry from runtime config.

## Solution

Extract a shared `QwenBaseModel` base class from the existing `QwenV5Model`, then derive thin wrappers `Qwen3_5_9BModel` and `Qwen3_8_27BModel` with compile-time geometry constants. The converter auto-detects the model variant from config.json geometry.

## Architecture

```
IModel
  └── QwenBaseModel (shared implementation, NOT registered in factory)
        ├── Qwen3_5_9BModel (final, kType="qwen3.5-9b", compile-time constants)
        └── Qwen3_8_27BModel (final, kType="qwen3.8-27b", compile-time constants)
```

### QwenBaseModel

Moves all current `QwenV5Model` logic (Load, Infer, Unload, Inspect, SelfCheck, Tokenizer) into a non-registerable base. Adds a protected virtual that logs a warning on mismatch but does NOT block Load():

```cpp
virtual void ValidateGeometry(const qwen::QwenTopology& top) const;
```

Called at the end of `Load()` after weights are loaded. The base implementation is a no-op. Derived classes override with compile-time constant checks that log `spdlog::warn` on mismatch but allow Load() to succeed — keeping synthetic test models working. Production models always match, so the warning never fires in real use.

### Qwen3_5_9BModel (replaces QwenV5Model)

```cpp
static constexpr int kHiddenSize = 4096;
static constexpr int kNumLayers = 32;
static constexpr int kNumHeads = 16;
static constexpr int kNumKVHeads = 4;
static constexpr int kHeadDim = 256;
static constexpr int kIntermediateSize = 12288;
static constexpr int kLinearNumValueHeads = 32;
static const std::string kType = "qwen3.5-9b";
```

ValidateGeometry logs `spdlog::warn("[qwen3.5-9b] geometry mismatch: expected hidden=4096 got N")` if any constant differs. Never blocks Load().

### Qwen3_8_27BModel (new)

```cpp
static constexpr int kHiddenSize = 5120;
static constexpr int kNumLayers = 64;
static constexpr int kNumHeads = 24;
static constexpr int kNumKVHeads = 4;
static constexpr int kHeadDim = 256;
static constexpr int kIntermediateSize = 17408;
static constexpr int kLinearNumValueHeads = 48;
static const std::string kType = "qwen3.8-27b";
```

Same pattern, different constants. ValidateGeometry logs comparable diagnostics when mismatched.

SelfCheck expects "Paris" as the canonical answer (identical tokenizer family).

## Converter auto-detection

In `WriteQwenModelIndex`, after loading config.json, detect variant:

```cpp
std::string model_name = "Qwen3.5-9B";  // default
if (top.hidden_size == 5120 && top.num_layers == 64 &&
    top.num_attention_heads == 24 && top.linear_num_value_heads == 48)
    model_name = "Qwen3.8-27B";
```

The detection uses the compound geometry fingerprint because:
- `hidden_size` and `num_layers` alone could overlap with future Qwen3.5 variants
- The full fingerprint (hidden_size, layers, heads, value_heads) is unique per known variant
- HF `_name_or_path` is not present in these config files; geometry is the reliable discriminator

## Known Limitations

Verified 2026-08-16 against the production checkpoint
(`D:\Programs\huggingface.co\Qwen3.8-27B`, RTX 5060 Ti 16GB):

- **Generation has no KV cache / recurrent state.** `RunQwenGeneration`
  (`libs/lsxcommon/src/qwen_inference.cu`) re-embeds and re-runs the *entire*
  growing sequence through all 64 layers on every decode step — full-attention
  layers recompute causal attention over the whole history, linear-attention
  layers recompute the GatedDeltaNet recurrence from scratch. This is O(N²) in
  generated tokens and does not scale to 64 layers: the `--run` prompt flag
  against the production 27B model did not finish a 64-token generation within
  40 minutes. The 9B model (32 layers) takes ~407 s for 64 tokens on the same
  host.
- **SelfCheck works and proves the math is correct**: `lsxfabric --selfcheck`
  against the production 27B checkpoint returns `'Paris'` (`passed=true`) in a
  few minutes (incremental decode of 1-2 tokens).
- **Practical scope**: the `--run` / `--testprompt` flags against the real 27B
  checkpoint are unusable until `RunQwenGeneration` implements incremental
  decode — a persistent per-layer K/V cache for `full_attention` layers and a
  persistent recurrent state `S[k,v]` for `linear_attention` layers. This is a
  follow-up, out of scope of the current integration.
