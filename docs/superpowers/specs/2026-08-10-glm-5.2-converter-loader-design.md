# GLM-5.2 Converter / Loader Design

## Purpose

Add end-to-end GLM-5.2 inference support alongside the existing
DeepSeek-V4-Flash path: a parallel converter (`ConvertGlmModel`) that emits the
logestix arrow layout, a host-side pinned-weights loader
(`LoadGlmPinnedWeights`), and an `IModel` implementation registered in the
model factory (`glm-5.2`). DeepSeek path is untouched.

## Scope

- `classify` – GLM tensor-name classifier (dense / MoE / indexer / MTP / global).
- `Topology` + `load_topology` – extended `logestix-x` index format
  (`moe_layers`, `dense_layers`, `indexer_layers`).
- `ConvertGlmModel` – full conversion pipeline (282-shard GLM-5.2 checkpoint).
- `SaveGlmPinnedTensors` / `WriteGlmModelIndex` – GLM pinned writers.
- `LoadGlmPinnedWeights` – host-only CUDA loader (BF16 → FP16 upload).
- `GlmV5Model` – `IModel` implementation, registry key `glm-5.2`.

## Index Format (`model.index.json`)

The DeepSeek uniform index (`logestix` format, all layers MoE) stays valid.
GLM emits an extended index:

```json
{
  "format": "logestix-glm",
  "model": "GLM-5.2",
  "num_layers": 79,
  "experts_per_layer": 256,
  "moe_layers": [3,4,...],
  "dense_layers": [0,1,2],
  "indexer_layers": [0,1,2,6,10,...],
  "total_pinned_tensors": 989,
  "total_experts": 19456
}
```

`model` is normalized by `detect_model_type` (`GLM-5.2` → `glm-5.2`) and drives
factory registration.

## File Naming (unpadded)

- `pinned/layer_<n>.arrow` (n unpadded, `std::to_string`)
- `pinned/global.arrow`
- `pinned/shared_experts.arrow` (one row per MoE layer, 9-col `ExpertSchema`)
- `pinned/tokenizer_vocab.arrow`, `pinned/tokenizer_merges.arrow`
- `experts/layer_<n>/exp_<m>.arrow`

## Storage / Dtype Model

GLM stores attention/pinned tensors as raw BF16 (no paired scales), unlike
DeepSeek's FP8. On upload:

- BF16 → FP16 (host-side bit path, mirrors `inference_load.cu`).
- `mlp.gate.e_score_correction_bias` (F32) → `cudaMallocHost` host pinned copy.
- `self_attn.indexer.k_norm.bias` (F32) → device `float*`.
- Routed/shared experts quantized NVFP4 via `PackExpertNVFP4` (raw BF16,
  `dtype_code 0`, 2 bytes).

## Geometry Constants (`glm_inference_load.h`)

Hidden 6144, layers 79, heads 64, head_dim 192, qk_nope 192, qk_rope 64,
head_v 256, q_lora_rank 2048, kv_lora_rank 512, moe_intermediate 2048,
num_routed 256, num_shared 1, indexer heads 32, indexer head_dim 128,
rms_eps 1e-5.

## Loader (`glm_inference_load.cpp`)

Pure host-side CUDA runtime API → compiled as a plain `.cpp` in `lsxcommon`
(not `lsxcommon_cu`). No device kernels.

Accept both layouts:

```
<model>/logestix/pinned/...   (model dir, like the DeepSeek loader)
<logestix>/pinned/...         (converter output_root)
```

`LoadGlmPinnedWeights` flow:

1. `glm::load_topology(index_path)` sizes `GlmPinnedWeights::layers`.
2. `pinned/global.arrow` → `LoadGlobal`: embed (sets `vocab_size`/`hidden`),
   `lm_head` (unless aliased), `model.norm`.
3. Per-layer `layer_<n>.arrow` → `LoadSingleLayer` (missing files skipped):
   - norms (`input_layernorm`, `post_attention_layernorm`)
   - MLA attention (`q_a_proj`, `q_a_layernorm`, `q_b_proj`,
     `kv_a_proj_with_mqa`, `kv_a_layernorm`, `kv_b_proj`, `o_proj`)
   - router (`mlp.gate.weight` BF16→FP16 + `e_score_correction_bias` F32 host)
   - dense MLP (layers 0–2, `gate_proj`/`down_proj`/`up_proj`)
   - indexer block (`wq_b`, `wk`, `weights_proj`, `k_norm` + F32 bias)
   - MTP extras (layer 78: `eh_proj`, `enorm`, `hnorm`, `shared_head.norm`)
4. Tensor lookup by full-name suffix match (`PinnedSchema::UnpackBatch`).

MLP/indexer shapes are intentionally not stored (null out-params).

## Tokenizer (`tokenizer_convert.cpp` fix)

GLM-5.2's `tokenizer.json` uses the modern HF **array merges** format:

```json
"merges": [["h","e"], ["he","l"], ...]
```

vs DeepSeek's string form `"h e"`. The converter now accepts both encodings; a
regression test covers the array form (321,649 real merges now round-trip).

## Model (`glm_v5_model.cpp`)

`GlmV5Model` mirrors `DeepSeekV4FlashModel`:

- `kType = "glm-5.2"`, registered in `model_registry.cpp`.
- `Load()` opens `logestix/pinned/tokenizer_*` via `load_tokenizer_metadata`.
- `Infer()`/`SelfCheck()` return "not implemented" (stub).
- `Inspect()` → `scan_directory`.

## lsxforge CLI

```bash
lsxforge --glm --input /path/GLM-5.2 --output /path/GLM-5.2/logestix
```

lsxfabric/lsxcli already route through `LsxModelFactory` autodetect.

## Real-Model Results (RTX 5090, sm_120)

- 282 shards scanned; 59,585 tensors; 0 unclassified/incomplete.
- 989 pinned tensors; 19,456 routed experts (76 layers × 256);
  76 shared-expert layers → `shared_experts.arrow`.
- Output: `pinned/` 32 GiB + `experts/` 385 GiB.
- `lambdafabric --testprompt/--selfcheck` autodetect `glm-5.2`, load tokenizer,
  reach the (stubbed) inference path.
