# Kimi-K2.7-Code — audit and re-adaptation design

Date: 2026-10-25
Branch: `feat/kimi-k2.7-code-audit` (from `main`)
Protocol: MODEL INGEST INVARIANT (Stage 0 triage + stages 1–8), TDD per stage
Scope: correctness first; throughput work is a separate iteration

## 1. Why this work exists

The family was ingested in 2026-08. Its synthetic suite is green, but in this
tree **nothing about the model has ever been verified against real weights**:

- no converted tree and no FSI/CODE/DET goldens
  (`docs/SELFCHECK_MATRIX.md` §4: "Neither — SKIP"), so every real-weight target
  reports SKIP, which is indistinguishable from a pass;
- the vault moved to `/mnt/fast_storage/huggingface` while the compile-time
  default is still `/mnt/llm_models/models`, so the skips are silent;
- the only attention test is partially circular (its CPU reference bakes in the
  kernel's own assumptions), and its tolerance (0.35 abs) cannot see an
  attention-temperature error;
- the tool-calling bridge is the generic Hermes fallback, while the checkpoint
  ships its own tool grammar.

Re-reading the checkpoint's own reference implementation
(`modeling_kimi_k25.py` → `modeling_deepseek.py`, shipped via `auto_map`), its
tokenizer class, and `transformers` 5.15.1 `deepseek_v3` found four blocking
defects (two in attention math, two in the token/stop policy). They invalidate
the August "Paris passes" claim as *parity* evidence: it was determinism only.

## 2. Source checkpoint (Stage 0, re-verified on disk)

Path: `/mnt/fast_storage/huggingface/Kimi-K2.7-Code`
Layout: multimodal wrapper `KimiK25ForConditionalGeneration`; text backbone
`DeepseekV3ForCausalLM` (`text_config.model_type = kimi_k2`), 64 shards,
208 550 tensors, ~581 GB.

Frozen geometry (all confirmed against the shard headers):

| item | value |
|---|---|
| hidden / layers | 7168 / 61 (layer 0 dense, 1..60 MoE) |
| heads / MLA | 64 heads; q_lora 1536; kv_lora 512; qk_nope 128; qk_rope 64; v_head 128 |
| attention projections | `q_a [1536,7168]`, `q_b [12288,1536]`, `kv_a [576,7168]`, `kv_b [16384,512]`, `o [7168,8192]`, all BF16 |
| MoE | 384 routed + 1 shared; top-8; `moe_intermediate_size` 2048; shared gate/up `[2048,7168]`, down `[7168,2048]` BF16 |
| dense FFN | layer 0, intermediate 18432 |
| router | `mlp.gate.weight` BF16 `[384,7168]` + `e_score_correction_bias` F32 `[384]`; sigmoid, noaux_tc, n_group 1, topk_group 1, `norm_topk_prob` true, routed scale 2.827 |
| rope | YaRN factor 64, original window 4096, `rope_theta` 50000, beta_fast 32, beta_slow 1, `mscale = mscale_all_dim = 1.0` |

| tokenizer | `tiktoken.model` ranks file + custom `pat_str` (Han-aware); specials in `tokenizer_config.json` |
| tokenizer policy (reference-verified) | `tok(text)` == `tok.encode(text)` == `tok(text, add_special_tokens=False)` → **no BOS/EOS is added**; `[BOS]` = 163584 exists but is never emitted; the generation stop id is `config.json` `eos_token_id` = 163586 (`<|im_end|>`), while `tokenizer_config.json` `eos_token` is the different `[EOS]` = 163585 |
| ballast | `vision_tower.*`, `mm_projector.*` (not applied) |

Semantics that matter and were re-derived from the reference:

1. **RoPE pairs adjacent dimensions.** The reference's `apply_rotary_pos_emb`
   does `view(..., d//2, 2).transpose(4,3).reshape(...)` before `rotate_half`,
   i.e. the effective rotation is on pairs `(x[2i], x[2i+1])` with
   `inv_freq[i]`; `transformers` DeepseekV3 defaults `rope_interleave = True`
   for the same reason. `rotate_half` on the *stored* layout (pairs
   `(i, i+32)`) is a different operator.
2. **The YaRN `mscale²` boost is part of `softmax_scale`.**
   `DeepseekV3Attention.__init__` multiplies `q_head_dim**-0.5` by
   `yarn_get_mscale(factor, mscale_all_dim)²` when `mscale_all_dim` is truthy.
   With factor 64, `mscale_all_dim = 1.0`:
   `mscale = 0.1*ln(64)+1 = 1.415888`, `scale = 192**-0.5 * mscale² = 0.144680`.
   The `cos/sin` `_mscale` ratio is 1.0 for this config (both mscale values 1).
3. Router, expert FFN, shared expert (weight 1.0), dense layer 0, residual
   order, final norm and BF16 `lm_head` were re-checked and match the reference.

## 3. Audit findings

Severity: **B** = blocker (wrong numerics), **D** = debt/gap, **M** = minor.

### F1 (B) RoPE pair layout is half-split
`kimi_kv_postprocess_kernel` rotates `(pair, pair+32)`. Reference rotates
`(2i, 2i+1)` (after a permutation that cancels in the attention dot). Measured
on the reference's own rope (`DeepseekV3YarnRotaryEmbedding` + its
`apply_rotary_pos_emb`), with `q` at position `p` and `k` at position 0:

| p | reference dot | engine convention |
|---|---|---|
| 1 | −18.688 | −10.186 |
| 2 | −14.422 | −15.711 |
| 3 | +0.201 | +5.494 |
| 4 | +15.277 | +10.734 |

At `p = 0` the two agree (angle 0), which is why a 1-token smoke test cannot
see it.

### F2 (B) Attention scale misses `mscale²`
`KimiAttnScale()` returns `rsqrt(192) = 0.0721688`; the reference uses
`0.1446796` (2.0047x). `kimi_moe_load.h` documents the contract as
`.../sqrt(192)*mscale`, so code and contract disagree. The attention test's CPU
reference *does* include the boost, but `CHECK(max_err <= 0.35)` absorbs it.

### F3 (D) No converted tree, no goldens, stale vault default
`kModelRootBase` (Linux) = `/mnt/llm_models/models` (does not exist). Real-weight
Kimi targets SKIP. `test_path_registry` pins the stale value.

### F4 (D) Stage 4b missing — generic Hermes only
`test_model_suite_guard.cpp` verdict row for `kimi-k2.7-code` is `{}` (generic).
The checkpoint's `chat_template.jinja` defines a native grammar
(`<|im_system|>`, `<|im_user|>`, `<|im_assistant|>`, `<|im_middle|>`,
`<think>…</think>`, `tool_declare` block, `<|tool_calls_section_begin|>`,
`<|tool_call_begin|>{id}<|tool_call_argument_begin|>{json}<|tool_call_end|>`,
`<|tool_calls_section_end|>`, `<|im_end|>`).

### F5 (D) Tokenizer never checked for token-level parity
`test_kimi_moe_tokenizer` "real vault" case only builds the Arrow files. The
merge reconstruction (min-max split heuristic) and the hand-ported
`pat_str`/pretokenizer are unverified against `tiktoken` (now installed, so an
oracle exists).

### F6 (D) Converter silently drops unknown tensors
69 120 `*.weight_shape` records plus vision/mm tensors are logged as
"Unclassified … (skipped)"; the index carries no ballast counts, so Stage 0.4's
"strip and COUNT" is not satisfied. Any genuinely unknown tensor would also only
warn.

### F7 (D) Async decode determinism is parked, not root-caused
`RunKimiGeneration` comments that fully-async decode reproduces a cross-cycle
`final_logits` divergence, so each step does a D2H + event wait. That is a
determinism defect hidden behind a serialization. It also allocates/frees
~700 MB of per-generation workspaces.

### F8 (D) Throughput
Last recorded 3.1 → 5.1 t/s (TC opt-in); the TC batch path is off by default
because it shifts the greedy top-1. Out of scope for this iteration (recorded,
not fixed).

### F9 (M)
- `kKimiMaxSlots = 1024` hard KV cap (config window 262 144) with no diagnostic;
- `resident_bytes` excludes the 1 GiB of lazily materialized `kv_b` BF16 planes;
- EOS is cut after the token has already been emitted on the stream;
- generation workspaces are per-call `cudaMalloc`/`cudaFree`.

### F10 (M, method) The August debug trail is a stale instrument
`/home/alexmv2025/projects/cuda/docs/KIMI_DEBUG_NEXT.md` explicitly dismisses
the `mscale²` boost and validated attention against a hand-written reference
that used the kernel's own pairing. Determinism ×3 was treated as parity.

### F11 (B) Encoder prepends a `[BOS]` the reference never emits
`BuildTokenizerArrowFilesTikToken` takes `bos_id` from
`tokenizer_config.json` (`[BOS]` = 163584, `>= 0`), and
`arrow_tokenizer_encode` prepends it. The checkpoint's tokenizer, loaded and
run (transformers 5.15.1 + `tiktoken`), returns plain ids for
`tok(text)`, `tok.encode(text)` and `add_special_tokens=False` alike:
`"The capital of France is"` → `[1008, 10484, 318, 15383, 387]`.
The engine therefore feeds `[163584, 1008, …]` — an extra token the model never
saw in that position, and one that shifts every RoPE position by one. Every
prompt, SelfCheck and FSI case is affected.

### F12 (B) The stop token is the wrong id
`Tokenizer().eos_id` comes from `tokenizer_config.json` `eos_token` =
`[EOS]` = 163585; the model's generation stop id is `config.json`
`eos_token_id` = `generation_config.eos_token_id` = 163586 (`<|im_end|>`), which
is also what `apply_chat_template` emits at the end of each message. Generation
therefore never cuts on the model's own end-of-turn token (it runs to
`max_gen_tokens`, and `TruncateAtEos` truncates nothing).

## 4. What we keep

The stack's structure is sound and stays: `kimi_moe_convert` (INT4 → NVFP4 per
expert, MLA projections quantized, norms/router/dense layer BF16), the pinned
expert store + device slot-LRU, the absorbed MLA decode kernel, the routed MoE
kernels, the lifecycle wiring, the guard registries. No file renames, no new
family, no kernel redesign.

## 5. Design

### 5.1 New instruments (written red first)

| instrument | oracle | what it pins |
|---|---|---|
| `tests/fixtures/kimi/rope_attn.json` + `test_kimi_moe_rope_parity.cu` | vectors captured by `tools/kimi_rope_capture.py` from the **vendored** `modeling_deepseek` (rope + score dots at positions 0..8) | F1 pairing and F2 scale: score abs error ≤ 1e-3 in f32, i.e. ~3 orders below the half-split error (O(1)) |
| `test_kimi_moe_attn_scale` (host-only case in the same TU) | `0.1*ln(64)+1` composed with `192**-0.5` | the scale constant as a one-line contract |
| `tests/fixtures/kimi/tokenizer_corpus.json` + `test_kimi_moe_tokenizer_parity` | `tools/kimi_tokenizer_capture.py` using the checkpoint's own tokenizer class (`tiktoken`, its `pat_str` and specials) | F5 exact id parity on a corpus (ASCII, digits, punctuation, contractions, whitespace runs, Cyrillic, CJK, emoji, long repeats, chat markers); the golden carries **no** BOS/EOS, matching `tok(text)` |
| `test_kimi_moe_tokenizer_policy` | `config.json` + the reference `tok(text)` | F11/F12: Arrow metadata `bos_id == -1` (never prepended), `eos_id == 163586`, `pad_id == 163839`, and `arrow_tokenizer_encode` of the SelfCheck prompt has no leading `[BOS]` |
| `tests/test_kimi_tool_framing.cpp` | hand-written expected frames from `chat_template.jinja` on a synthetic tokenizer | F4 render + parse round-trip |
| `test_kimi_moe_attention` (existing) | CPU reference switched to the reference convention, tolerance tightened to `2e-2` | removes the circularity, keeps the kernel honest |

Fixture capture scripts are host-only Python tools under `tools/`; the goldens
are committed JSON, and the capture command is recorded in the fixture header,
so the instrument is reproducible (the OPEN_ENDEDNESS rule: external oracle,
never the engine's own output).

### 5.2 Semantics fixes

- `kimi_kv_postprocess_kernel`: rotate adjacent pairs for both `q_rope`
  (per head) and `k_rope`; the absorbed MLA form is unchanged (the permutation
  cancels inside the q·k dot, so no other kernel changes).
- `KimiAttnScale()`: `rsqrtf(192) * mscale * mscale` with
  `mscale = 0.1f*logf(kKimiYarnFactor) + 1.0f`, frozen as
  `kKimiYarnMscale`/`kKimiAttnScale` beside the passport constants and
  `static_assert`ed against the header's documented contract
  (`.../sqrt(192)*mscale`).

### 5.3 Stage 4b — native tool bridge

New model-owned pair `kimi_moe_tool_format.{h,cpp}` (added to
`test_code_naming_guard`'s `AllowedCommon`, same commit), following
`deepseek_moe_tool_format`:

- render: `system` → `<|im_system|>{name}<|im_middle|>{text}<|im_end|>`;
  `user`/`assistant` likewise; `assistant` body = `<think>{reasoning}</think>`
  + content + tool-calls section; `tool` → `## Return of {id}\n{content}`;
  `tools` → one `<|im_system|>tool_declare<|im_middle|>{json}<|im_end|>` frame;
  generation prompt = `<|im_assistant|>assistant<|im_middle|><think>`.
- parse: scan the decoded text for `<|tool_call_begin|>{id}<|tool_call_argument_begin|>{json}<|tool_call_end|>`,
  then fall back to `tools::ParseToolCallsText` / `ParseBareToolCallJson`.
  Markers whose `added_tokens` entry is `special: true` are matched from ids
  (the engine's decode skips specials), escaped markers from text.
- wire `BuildConversationInputIds` / `ParseToolCalls` in `KimiK27CodeModel`;
  update the suite-guard tool verdict row and AGENTS.md.

### 5.4 Converter

- classify `vision_tower.*`, `mm_projector.*`, `*.weight_shape` explicitly,
  count them, and write `skipped_visual_tensors`, `skipped_shape_tensors`,
  `mtp_layer: null` into `model.index.json`;
- any other unclassified tensor becomes a hard error (Stage 7 of the skill:
  never skip the unknown ones);
- keep the offset-binary INT4 decode (`(nib - 8) * scale`), now pinned by a
  source-only oracle: `test_kimi_moe_int4_source_oracle` reads one real expert
  straight from the source shards, checks the nibble histogram is offset by 8,
  reconstructs the BF16 weight and compares against the NVFP4 round-trip of the
  same tensor (bounded relative error), without needing the converted tree;
- extend the synthetic E2E fixture with a `weight_shape` record and assert the
  new counts.

### 5.4b Tokenizer policy (F11/F12)

`BuildTokenizerArrowFilesTikToken` gains an explicit policy parameter
(`struct TikTokenSpecialPolicy { int32_t bos, eos, pad; bool from_model_config; }`);
the default keeps today's `tokenizer_config.json` derivation for any other
caller, and the Kimi converter passes the values read from **`config.json`**
(`text_config.eos_token_id` 163586, `pad_token_id` 163839) with
`bos = -1` — the reference tokenizer never emits `[BOS]`. The values are
cross-checked against the frozen passport (a mismatch fails the conversion).
Consequences pinned by tests: `arrow_tokenizer_encode(prompt)` carries no
leading 163584, `Tokenizer().eos_id == 163586`, and generation stops on
`<|im_end|>` instead of running to `max_gen_tokens`.

### 5.5 Vault

`kModelRootBase` (Linux) → `/mnt/fast_storage/huggingface`; update
`test_path_registry`. Kimi targets already resolve through
`lsx_model_models_dir()`; docs referencing `/mnt/llm_models/models` for Kimi are
updated. Other families' hardcoded literals are out of scope (noted in
`docs/OPEN_TASKS.md`).

### 5.6 Re-conversion and real-weight verification

`LSX_MODEL_ROOT=/mnt/fast_storage/huggingface lsxforge --kimi
--input …/Kimi-K2.7-Code --output …/Kimi-K2.7-Code` (~542 GiB, hours). Then:

1. index/manifest checks: layer count 61, 384 experts × 60 layers = 23 040,
   61 pinned layer files, ballast counters, tokenizer arrows;
2. `test_kimi_moe_int4_real` (source vs converted payload) + the new source
   oracle;
3. SelfCheck `"The capital of France is"` → Paris, ×3 cycles, bit-exact
   `final_logits`;
4. **layer oracle**: `tools/kimi_layer_oracle.py` runs one *reference* decoder
   layer on the source tensors (BF16 attention, INT4 experts dequantized in
   float) and compares against the engine's env-gated hidden-state dump for the
   same input ids (layers 0, 1, 30, 60), asserting bf16-quantization-level
   agreement. This is the instrument that would have caught F1/F2;
5. streaming + abort and the lifecycle contract (`test_streaming_assert.h`);
6. perf measured once and recorded through the harness (`test_perf_baseline`),
   not hand-edited.

### 5.7 F7 — determinism

Reproduce the divergence with the env dump, identify the root cause (candidate:
expert-cache slot upload vs compute fence, or the accumulate order across
experts), fix it, and only then remove the per-step readback. If it cannot be
root-caused in this iteration, keep the serialization and record the defect with
the instrument that reproduces it in `docs/OPEN_TASKS.md` — no silent parking.

### 5.8 Parity gates

FSI/CODE/DET goldens require running the source model (581 GB, INT4,
`compressed-tensors` not installed). Attempt a real capture on CPU with a
memory-bounded reference (install `compressed-tensors`, `device_map=cpu`,
8 prompts); if the host cannot complete it, record an explicit `kGoldenDebt`
row with the measured reason (mistral/nemotron precedent) in
`test_model_suite_guard.cpp`, `docs/SELFCHECK_MATRIX.md`, `docs/OPEN_TASKS.md`.
Goldens are never derived from the engine.

## 6. Acceptance criteria

- [ ] new oracles red before the fix, green after; no circular references
- [ ] tokenizer: corpus id parity exact, no leading `[BOS]`, `eos_id == 163586`
- [ ] converted tree loads; `resident:` reported; 23 040 experts + 61 layers
- [ ] SelfCheck Paris ×3, bit-exact `final_logits`, and generation stops on
      `<|im_end|>` (163586) rather than at the token budget
- [ ] layer oracle agrees within the bf16/quantization tolerance at layers 0/1/30/60
      (relative L2 ≤ 2% per layer, and the layer's top-1 logit ordering preserved)
- [ ] native tool framing: render matches `chat_template.jinja`, parse round-trip
      green on a synthetic tokenizer
- [ ] `test_model_suite_guard`, `test_model_independence_guard`,
      `test_code_naming_guard`, `test_ctest_labels_guard`,
      `test_expert_store_guard` green
- [ ] every numeric claim names its oracle; gate verdicts written into
      `docs/SELFCHECK_MATRIX.md` (pass or measured debt)
- [ ] `AGENTS.md` Structure entry updated

## 7. Risks

- conversion time/disk (581 GB read, ~542 GiB write, 9.9 TB free);
- FSI/CODE/DET capture may be infeasible on one 5090 + 750 GB RAM → declared debt;
- F7 root cause may be deeper than this iteration (then it is recorded, not hidden);
- 1024-slot KV cap means long-context validation is out of reach here.

## 8. Out of scope

Throughput (100 t/s plan, TC-batch re-enable), long-context KV growth, vision
tower, other families' vault-path literals.
