# Qwen3.5-9B real-weight completion design

## Context

The Qwen3.5-9B **code** integration is already committed and green on `main`:

- shared dense contour `QwenBaseModel`
  (`libs/lsxcommon/src/qwen_base_model.{h,cpp}`) driven by
  `Qwen3_5_9BModel` (`libs/lsxcommon/src/qwen_dense_model.{h,cpp}`),
  registry `kType = "qwen3.5-9b"` (`model_registry.cpp:30`);
- converter `qwen_dense_convert.cpp` (auto-detects the 9B and defaults the
  index `model` name to `"Qwen3.5-9B"`, `qwen_dense_convert.cpp:385`), host
  loader `qwen_inference_load.cpp`, CUDA kernels `qwen_inference.cu` on the
  neutral `lsx_gemv`/NVFP4 path (no cuBLAS);
- all 8 lifecycle stages registered in `test_model_suite_guard.cpp:126`
  (convert/load/model/kernels/selfcheck/fsi/code/det).

What is **not** done is the real-weight path:

- the source checkpoint `/mnt/llm_models/models/Qwen3.5-9B` is **not
  converted** — there is no `logestix/pinned/`, so `test_qwen_dense_selfcheck`
  SKIPs;
- the FSI/CODE/DET gates `test_qwen_dense_{fsi,code,det}_selfcheck` have
  **no committed goldens**
  (`tests/fixtures/{fsi,code,det}/qwen3.5-9b.json` are absent), so they SKIP;
- `test_perf_baseline_qwen3_5_9b` has no `perf_baselines.json` entry because
  the model was absent from the vault (`docs/OPEN_TASKS.md:309`).

A prior fused-decode attention path was KNOWN-BROKEN on the real 9B
checkpoint and was deleted by the 2026-09 model-independence audit
(`test_model_independence_guard.cpp:340`); the live decode path is split-KV.
This spec closes the real-weight gap, mirroring the just-completed Qwen3.8-27B
completion (`2026-10-01-qwen3.8-27b-realweight-design.md`), which shares the
same dense contour and already added the `qwen3_5` VLM capture loader.

## Source checkpoint (frozen facts, 2026-10-01)

`/mnt/llm_models/models/Qwen3.5-9B` (19 GiB, 4 BF16 shards), HF `config.json`:
`architectures=["Qwen3_5ForConditionalGeneration"]`, `model_type="qwen3_5"`,
text geometry under `text_config`:

- hidden 4096, 32 layers, 16 Q / 4 KV heads, head_dim 256, intermediate 12288,
  `attn_output_gate` true, `attention_bias` false;
- linear attention: 16 key heads / 32 value heads, key/value head dim 128,
  `linear_conv_kernel_dim` 4;
- `layer_types` = 3x `linear_attention` + 1x `full_attention`, repeating
  (`full_attention_interval` 4);
- `partial_rotary_factor` 0.25 (rotary 64 of 256), `rope_theta` 1e7,
  `mrope_interleaved` true, `rms_norm_eps` 1e-6, vocab 248320,
  eos 248044, `mtp_num_hidden_layers` 1, `mamba_ssm_dtype` float32,
  `tie_word_embeddings` false;
- vision (`vision_config`: depth 27, hidden 1152, out_hidden 4096) and
  `model.visual.*` weights are present but stripped.

Tensor inventory (775): `model.language_model.*` 426, `model.visual.*` 333
(vision — stripped), `mtp.*` 15 (multi-token-prediction — stripped),
`lm_head.weight` 1.

The Python capture environment (transformers 5.15.1, torch 2.13) loads this
VLM as a text-only `Qwen3_5ForCausalLM` via the existing `qwen3_5` loader in
`tools/{fsi,code,det}_capture.py` (key remap
`model.language_model.` -> `model.`, `model.visual.*`/`mtp.*` dropped).

## Approach

1. **Real conversion** (existing code): `lsxforge --qwen
   --input=/mnt/llm_models/models/Qwen3.5-9B
   --output=/mnt/llm_models/models/Qwen3.5-9B` (in-place `logestix/`). The
   converter auto-detects the 9B and strips vision/MTP with counting. Expected
   footprint ~5 GiB NVFP4. GPU-exclusive.
2. **Validation**: `lsxfabric --localmodel <root> --validate` and
   `lsxcli --model <root> --info` (type `qwen3.5-9b`, 32 layers, hidden 4096,
   16/4 heads, 32 value heads, vocab 248320).
3. **Paris gate**: `test_qwen_dense_selfcheck` must PASS (not SKIP):
   `"The capital of France is"` -> `"Paris"` with >=3 bit-exact cycles.
4. **Correctness root-cause (only if the gate diverges)**: reproduce with
   `LSX_TEST_QWEN_SELFCHECK_CYCLES=1`, compare per-layer against the HF source
   (`_load_qwen3_5`), consult the mirrored CUDA docs under
   `/home/alexmv2025/projects/cuda/docs` before any kernel edit, and fix the
   runtime — never the assertion.
5. **Golden capture (small code change, TDD)**: add
   `"qwen3.5-9b": {"loader": "qwen3_5", "device_map": "auto"}` to the
   `OVERRIDES` table of `tools/{fsi,code,det}_capture.py`. No loader code is
   new (the `qwen3_5` remap exists from the 27B work); test-first by extending
   each tool's `--selftest` to assert the override resolves to the `qwen3_5`
   loader before adding the row. Then capture the three goldens from the
   **source** safetensors.
6. **Gates**: run `test_qwen_dense_{fsi,code,det}_selfcheck` against the
   converted model at `kOff`; a divergence is a real finding to investigate,
   never a gate to loosen.
7. **Docs/guards**: record capture recipes/outcomes in
   `docs/{FSI,CODE,DET}_SELFCHECK_FINDINGS.md`; the 9B rows already exist and
   record "source absent from the vault" — update them to the captured status.
   Keep `test_model_suite_guard` / `test_model_independence_guard` /
   `test_code_naming_guard` / `test_ctest_labels_guard` green. Stages are
   already wired, so no registry change is expected.
8. **Perf last, GPU-exclusive**: run `test_perf_baseline_qwen3_5_9b` at the
   canonical 2048-token protocol to seed the missing `perf_baselines.json`
   entry, then profile one decode token with nsys and apply a low-risk
   optimization only if a clear serial bottleneck appears.

## TDD

The golden overrides are the only new "code" (Python tools). Test-first: the
per-tool `--selftest` gains an assertion that `"qwen3.5-9b"` maps to
`loader == "qwen3_5"`, which fails before the `OVERRIDES` row exists, then the
row. The existing `--selftest` paths must stay green.

The real-weight gates themselves are executable tests that already exist; the
conversion/validation/golden steps make them run instead of SKIP. No test
assertion is relaxed to make a gate pass.

## Risks

- **Real-weight divergence**: the 9B is the first checkpoint of this geometry
  exercised on real weights (the 27B has different shapes and does not satisfy
  `hidden == heads * head_dim`). Divergence is possible; the resolution is
  root-cause with the HF reference and mirrored CUDA docs, not loosening.
- **Capture cost**: bf16 9B (~19 GiB) fits the 32 GiB GPU, so capture is
  single-device and fast relative to the 27B (which needed CPU offload).
- **Golden extraction fragility**: the FSI/CODE/DET extractors are sensitive
  to reasoning echoes; a mismatch is checked against the golden `raw` before
  being treated as a runtime defect (see the findings docs).

## Out of scope

New kernels unless a real-weight defect demands one, tool-calling work (the
qwen ChatML/XML codec is already verified), vision/MTP inference, Windows, and
perf tuning beyond seeding the baseline and acting on an obvious bottleneck.
