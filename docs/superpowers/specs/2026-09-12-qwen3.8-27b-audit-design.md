# Qwen3.8-27B Integration Audit + Perf Baseline — Design

Date: 2026-09-12
Status: approved

## Goal

Full audit of the Qwen3.8-27B integration (all lifecycle stages) and fixation
of its maximum generation speed on the current hardware (RTX 5090, Linux)
per the committed perf-baseline rules.

## Current state

- Integration code exists (session 2026-08-15): `Qwen3_8_27BModel` on shared
  `QwenBaseModel` (`libs/lsxcommon/src/qwen_dense_27b_model.{h,cpp}`),
  converter auto-detect of the 27B variant (hidden=5120, layers=64,
  `qwen_dense_convert.cpp`), registry `"qwen3.8-27b"`, synthetic tests
  (`tests/test_qwen_dense_27b_{model,selfcheck}.cpp`).
- Missing: converted model in the vault
  (`/mnt/llm_models/models/Qwen3.8-27B/logestix/`), perf-baseline entry in
  `tests/perf/perf_baselines.json`, perf-baseline test case.

## Decisions (operator-approved)

- Audit runs in `linux-debug`; speed measurements in
  `linux-release-znver4-aocc`.
- Approach B: staged audit with real e2e and per-stage validation.

## Plan (stages)

1. **Static audit vs Model Ingestion Protocol** (8 stages): converter
   topology/passport, NVFP4 policy (dense matrices E2M1+E4M3+global_scale;
   norms/biases stay FP16/BF16), factory + `static_assert` geometry (27B uses
   relational invariants: `hidden(5120) != heads(24)·head_dim(256)` is
   legitimate for this topology), token bridge (bos/eos/pad from config),
   CUDA kernels (shared dense qwen contour; stream/stride invariants),
   shared-memory RMW discipline, passport (shared infra
   `model-metadata/passport.bin`; precedent qwen3.5-9b — no per-model
   passport), TDD/selfcheck harness. Defects (if any) are fixed before
   proceeding.
2. **Synthetic suites** (linux-debug): `ctest -R "qwen_dense_27b"` + full
   fast suite green.
3. **Real conversion**: `lsxforge --qwen --input=/mnt/llm_models/models/Qwen3.8-27B
   --output=/mnt/llm_models/models/Qwen3.8-27B` → `logestix/` + `pinned/`
   layout (~15-16 GiB NVFP4, fits 32 GiB VRAM). Then `lsxfabric --validate`.
4. **Real selfcheck** (linux-debug): `test_qwen_dense_27b_selfcheck` —
   "Paris", 3 bit-exact cycles (previously SKIPped without the model).
5. **TDD perf-baseline**: add
   `TEST_CASE("perf baseline: qwen3.8-27b")` to `tests/test_perf_baseline.cpp`
   + ctest entry `test_perf_baseline_qwen3_8_27b` (label `perf`, TIMEOUT).
   Protocol identical to other models: prompt "The capital of France is",
   max_gen 2048. First run: entry absent → `JudgePerf` → `kUpdate` → the test
   writes the baseline into `tests/perf/perf_baselines.json` (GREEN); second
   run → `kPass` (tolerance -3%).
6. **Max speed measurement** (linux-release-znver4-aocc): GPU-exclusive
   discipline (no parallel GPU jobs). Authoritative measurement via
   `ctest -R test_perf_baseline_qwen3_8_27b` on the release build; control
   duplicate via `lsxbenchmark --bench` for the t/s/ttft report.

## Commits

- `docs:` design doc (this file, before implementation)
- `fix:`/`feat:` audit defects, if any
- `test: qwen3.8-27b perf baseline registration` (stage 5-6 artifacts)

## Risks

- Conversion reads 18 safetensors shards (~54 GiB BF16); GPU quantization is
  per-tensor, VRAM is sufficient.
- If selfcheck does not produce "Paris", root-cause before measuring — a
  speed number on a broken model is meaningless.
