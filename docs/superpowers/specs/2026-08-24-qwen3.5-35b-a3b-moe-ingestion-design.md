# Qwen3.5-35B-A3B (MoE) — Design

Date: 2026-08-24
Status: approved design, pending implementation plan
Branch: `feat/qwen3.5-35b-a3b`

## Overview

Ingest Qwen3.5-35B-A3B (`Qwen3_5MoeForConditionalGeneration`, model_type
`qwen3_5_moe`) into the logestix monorepo following the 8-step Model Ingestion
Protocol and the established etalons:

- **Converter / topology**: Gemma4-26B-A4B (`gemma4_convert.cpp`) — MoE config fields.
- **Expert on-disk layout + on-demand residency**: GLM-5.2 (`experts/layer_N/exp_E.arrow`,
  `GlmExpertDeviceCache` LRU device-slot cache).
- **Attention kernels**: Qwen3.5-9B (`qwen_inference.cu`) — same hybrid
  linear/full attention family.
- **Lifecycle**: `MoEStrategy` (`lifecycle_strategy.h`) — expert cache slot budgeting.

Approach A (approved): self-contained MoE pipeline; dense Qwen path untouched.

Source checkpoint (read-only): `/mnt/llm_models/models/Qwen3.5-35B-A3B`.

## Frozen geometry (compile-time)

Locked in a new `qwen_3_5_moe_model.h` constants block with `static_assert`;
`ValidateGeometry()` compares parsed topology against constants at load;
escape hatch `LSX_TEST_ALLOW_SYNTHETIC_GEOMETRY` (pattern:
`test_qwen_3_8_27b_model`).

| Constant | Value | Notes |
|---|---|---|
| kHidden | 2048 | |
| kLayers | 40 | all layers MoE (`mlp_only_layers=[]`) |
| kFullAttnInterval | 4 | full attention at layers 3,7,...,39 (config `layer_types`); others linear (gated delta) |
| kHeads | 16 | full attention |
| kKVHeads | 2 | GQA 16:2 |
| kHeadDim | 256 | topology does NOT satisfy hidden==heads*head_dim (16*256=4096 ≠ 2048); relational asserts only (27B pattern) |
| Linear attn | key 16×128, value 32×128, conv_kernel=4 | |
| kNumExperts | 256 | `static_assert(kTopK <= kNumExperts)` |
| kTopK | 8 | `norm_topk_prob=true`, no routed scaling factor (1.0) |
| kMoeIntermediate | 512 | |
| kSharedIntermediate | 512 | + scalar gate `shared_expert_gate` |
| kVocab | 248320 | |
| eos_id | 248044 | from config; bos/pad per tokenizer_convert defaults policy |
| Rope | theta 1e7, partial_rotary_factor 0.25 | mrope sections ignored for text-only path (verify parity vs HF during planning) |

Multimodal vision tower (`visual.*`, 333 tensors) is stripped at conversion and
recorded as intentionally skipped in the manifest. The MTP block IS converted
and stored (operator decision), but NOT applied at inference: verified against
the HF reference (`transformers/models/qwen3_5_moe/modeling_qwen3_5_moe.py`
lists `^mtp.*` as `_keys_to_ignore_on_load_unexpected`) — standard generation
excludes MTP from the graph. The Infer loop follows HF parity exactly; MTP
weights stay resident-on-disk for future speculative decoding.

## Converter (protocol steps 1–2)

New files:

- `libs/lsxcommon/include/lsxcommon/qwen_moe_convert.h`
- `libs/lsxcommon/src/qwen_moe_convert.cpp`

Entry point: `arrow::Status lsxcommon::qwen_moe::ConvertQwen35MoeModel(
const std::string &input_dir, const std::string &output_root)`.

New lsxforge flag `--qwen35moe` dispatched in `apps/lsxforge/src/main.cpp`
(alongside `--glm/--kimi/--qwen/--gemma4`, lines ~365-406). Separate flag per
operator decision — dense `--qwen` pipeline stays untouched.

Behavior:

1. Parse `text_config` from `config.json` via simdjson (etalon:
   `gemma4_convert.cpp:134-155`): hidden_size, num_hidden_layers,
   layer_types/full_attention_interval, head_dim, heads, kv_heads, linear_* dims,
   num_experts, num_experts_per_tok, moe_intermediate_size,
   shared_expert_intermediate_size, rms_norm_eps, rope params, vocab_size,
   eos_token_id.
2. Classify tensors by prefix `model.language_model.*`, `mtp.*`; regex classifier
   modeled on `classify_qwen_tensor`. Vision prefix → deliberate skip list.
3. NVFP4 quantization policy (`qwen_tensor_is_nvfp4` analog):
   - Quantized (E2M1 nibbles packed + per-block E4M3 scales + f32 global_scale):
     q/k/v/o projections, linear-attn in/out projections, embeddings, lm_head,
     fused expert weights, shared expert weights.
   - High precision BF16/FP16 (INVARIANT: norms and biases are never quantized):
     input/post_attention layernorms, QK-norms, linear_attn norm/A_log/dt_bias/conv1d,
     router `mlp.gate.weight`, `shared_expert_gate`, final norm.
4. Expert split: fused `mlp.experts.gate_up_proj [256, 2048, 1024]` → per-expert
   w1 (gate half) / w3 (up half); `down_proj [256, 512, 2048]` → w2. Written as
   `ExpertSchema` records (9 columns, `schema.h`) to
   `<out>/experts/layer_<N>/exp_<E>.arrow` — GLM layout, required for on-demand mmap.
5. Shared expert per layer → one record/layer (SharedExpertSchema pattern);
   its scalar gate kept FP16 alongside.
6. MTP block (`mtp.fc`, `mtp.layers.0.*` incl. its own 256-expert MoE) →
   converted to the same formats under an `mtp/` subtree.
7. Structural manifest + `model.index.json` with format tag `"logestix-qwen35moe"`.
   All paths through authority `lsx_model_metadata(rel)` /
   `lsx_model_metadata_root()` (`path_registry.cpp`); zero hardcoded paths.
8. Integrity: `integrity::VerifyAllTensorReads`, tensor coverage check with
   explicit accounting of vision-skips and MTP inclusion, layer contiguity,
   geometry cross-check vs config. VRAM profile written to manifest.

## Loader, memory, lifecycle (protocol step context)

New files:

- `libs/lsxcommon/include/lsxcommon/qwen_moe_inference_load.h`
- `libs/lsxcommon/src/qwen_moe_inference_load.cpp`

Host loader `LoadQwenMoePinnedWeights()` (etalon: `LoadGlmPinnedWeights`,
`glm_inference_load.cpp`):

- Pinned staging ring; per-layer device arenas for dense parts (attention,
  norms, router, shared expert); fast path BF16→FP16 in-place where applicable.
- Strict errors on missing layer files / malformed tensors.
- Routed experts are NOT resident: `experts/layer_N/exp_E.arrow` opened via
  mmap; H2D staging into device slots on demand.

Device cache `QwenMoeExpertDeviceCache` — adaptation of
`GlmExpertDeviceCache` (`glm_expert_cache.h`), same layout
(`[slots][pack_stride | scale_stride]`, host-side LRU bookkeeping inline
helpers unit-testable without CUDA, hit/miss counters). Lives in the qwen_moe
namespace; GLM code untouched.

Lifecycle: new `Qwen35MoeStrategy : public MoEStrategy` in
`lifecycle_strategy.{h,cpp}` computes `expert_cache_slots` from expert mean
bytes (~1.7 MB NVFP4 per expert) and free VRAM bounds (TuningBounds pattern).
MTP subtree stays on disk (converted, unused by the standard Infer loop —
HF parity decision above).

## CUDA kernels (protocol steps 5–6)

New file `libs/lsxcommon/src/qwen_moe_inference.cu` → new OBJECT library
`lsxcommon_qwen_moe_cu` in `libs/lsxcommon/CMakeLists.txt` (flags like
`lsxcommon_qwen_cu`: Blackwell arches only, `--extended-lambda`,
`-fmad=false` for bit-exact math), linked PUBLIC into `lsxcommon`.

- Router: cuBLAS BF16-router × FP16-hidden logits [seq, 256] →
  `qwen_moe_router_topk_kernel`: softmax over all experts, top-8 selection,
  renormalize coefficients (`norm_topk_prob=true`, scale 1.0). Routing record
  `struct alignas(8) QwenMoeRoutedSlot { int32_t eid; float coeff; }`
  (pattern: `GlmRoutedSlot`).
- Routed expert FFN: NVFP4 decode (E2M1 table + E4M3 per-block scales) →
  SwiGLU(w1·x, w3·x) → w2 → weighted scatter-add across top-8; reuses the
  nvfp4 tile-GEMM machinery from recent commits (shared E2M1 table, register
  prefetch / dual accumulator chains where applicable).
- Shared expert FFN: same decode/SwiGLU path + elementwise multiply by
  `sigmoid(shared_expert_gate(h))`; added to routed output.
- Attention: adapt/reuse 9B kernels from `qwen_inference.cu`
  (`qwen_gated_delta_kernel` for linear layers, full-attention path for every
  4th layer) under new dims (hidden 2048, 16×256, GQA 16:2), adding QK-Norm
  (per-head RMSNorm) and sigmoid output gating; RoPE theta 1e7 with partial
  rotary factor 0.25.
- Protocol invariants:
  - Single end-to-end `cudaStream_t` for the whole generation loop; no
    `cudaDeviceSynchronize` per token (final sync only).
  - Any shared-memory RMW is isolated: writes by thread 0 only, hard
    `__syncthreads()` barriers, read-only afterwards (etalon:
    `full_attn_softmax_kernel`).
  - Q/K/V addressing strictly by physical tensor strides; no temporal overlap.
  - Bit-exactness: `-fmad=false` on math-critical kernels; deterministic
    reduction order (shuffle/tree reduce etalon `qwen_reduce.cuh`).

## Model class, registry (protocol step 3)

New files:

- `libs/lsxcommon/src/qwen_3_5_moe_model.h` (constants + class decl)
- `libs/lsxcommon/src/qwen_3_5_moe_model.cpp`

`class Qwen35MoeModel final : public lsxcommon::ModelBase` (directly on
ModelBase — NOT the dense QwenBaseModel; standalone-model pattern of
GlmV5Model / KimiK27CodeModel / DeepSeekV4FlashModel).
`static constexpr const char* kType = "qwen3.5-35b-a3b";` registered in
`EnsureModelRegistry()` (`model_registry.cpp`).

Implements Load/Infer/Unload/Inspect/SelfCheck/Tokenizer:

- Infer loop: embed → 40 layers (linear/full attention per interval-4 pattern;
  each layer: RMSNorm → attn → residual → RMSNorm → MoE FFN (router top-8 +
  shared expert)) → final norm → lm_head logits (no MTP application — HF parity).
- SelfCheck: incremental 1→2-token generation forced to
  `max(2, max_gen_tokens)`; prompt "The capital of France is" must yield
  "Paris" (top-1 of first decoded token/prefix); publishes `gen_tokens` +
  `final_logits` in InferenceResult (GLM SelfCheck pattern).

## Token bridge + passport (protocol steps 4, 7)

- Tokenizer: BPE via `BuildTokenizerArrowFiles` from the checkpoint's
  `tokenizer.json` / `vocab.json` + `merges.txt` (array-format merges
  supported); bos/eos/pad read from config (`eos_token_id=248044`), never
  hardcoded in kernels.
- Passport scope note (resolved during planning): `passport.bin` is the fixed
  GLM↔DeepSeek orchestrator translation bridge (`lsx_token_translator.h`);
  its format has no qwen slots. Extending it for qwen↔deepseek translation is
  a separate sub-project. IoWorker integration unchanged by this ingestion.

## Risks / open verification points (resolved during planning)

1. RESOLVED: 9B attention kernels are fully runtime-parameterized by
   `qwen::QwenTopology` (dims flow as kernel args; no 9B constants inside
   kernels) — reuse is direct, no adaptation needed beyond wiring.
2. RESOLVED: partial rotary factor 0.25 is natively supported
   (`partial_rope_kernel` + `rotary_dim = HD * partial_rotary_factor` at
   `qwen_inference.cu:1369`); theta passes through config. mrope sections are
   ignored for the text-only path.
3. RESOLVED: fused `gate_up_proj[e]` is `[2I, H]`; HF chunks gate=rows[0,I),
   up=rows[I,2I) (`modeling_qwen3_5_moe.py`, `Qwen3_5MoeExperts.forward`).

## TDD test plan (protocol step 8)

Tests are written FIRST (red→green) per unit, each against a synthetic
mini-checkpoint fixture modeled on `tests/gemma4_test_fixture.h`. All real-model
cases SKIP without the checkpoint (`SKIP_RETURN_CODE 4` pattern).

| Test executable | Covers |
|---|---|
| `tests/test_qwen_moe_convert.cpp` | text_config parsing; tensor classification; vision skip accounting; fused gate_up split w1/w3 correctness; NVFP4 policy (norms/biases/router stay high precision); integrity failure modes; index format tag |
| `tests/test_qwen_moe_loader.cpp` | pinned load roundtrip; expert store layout; strict missing-file/malformed-tensor errors; E4M3 scale decode |
| `tests/test_qwen_moe_kernels.cu` | router softmax+top8+renorm bit-exact vs host replica; E2M1/E8M0 decode; SwiGLU; shared-gate multiply; LRU `CacheLookup`/`CacheInsert` semantics (host-side, no CUDA launch needed) |
| `tests/test_qwen_moe_model.cpp` | registry lookup by kType; ValidateGeometry gates incl. synthetic-env behavior; Inspect fields |
| `tests/test_qwen_moe_selfcheck.cpp` | incremental 1→2-token SelfCheck, ≥3 stress cycles (override via new `LSX_TEST_QWEN_MOE_SELFCHECK_CYCLES`), bit-exact `final_logits` across cycles, exit 0 |

CMake wiring in `tests/CMakeLists.txt` following existing patterns: host tests
link `lsxcommon Catch2::Catch2WithMain` (+ Win32 arrow dll POST_BUILD copy);
kernel tests via OBJECT lib `test_qwen_moe_cu` (arch 120/121-real,
`--extended-lambda --expt-relaxed-constexpr`); selfcheck test links
`lsxcommon` only with SKIP_RETURN_CODE 4; non-selfcheck tests get
`ENVIRONMENT "LSX_TEST_ALLOW_SYNTHETIC_GEOMETRY=1"`.

## Error handling

- Converter: hard error on missing config/safetensors shards, unknown tensor
  prefixes outside {language_model, mtp, visual} (visual = counted skip),
  geometry mismatch vs frozen constants, failed integrity checks.
- Loader: hard error on missing layer/expert files or malformed arrow records
  (no silent fallbacks) — GlmPinnedWeights strictness.
- Runtime: OOM on cache allocation → actionable message with computed slot
  budget from LifecycleStrategy; router degenerate cases (NaN logits) fail fast.

## Risks / open verification points (resolve during planning)

1. Reuse degree of 9B attention kernels under new dims — if not parameterized,
   adapt (copy+specialize) inside `qwen_moe_inference.cu`.
2. RoPE parity: partial_rotary_factor 0.25 + interleaved mrope config — verify
   exact HF formula for the text-only path before implementing kernel details.
3. Fused gate_up ordering (gate-first vs up-first halves) — verify against HF
   `Qwen3_5MoeTextSparseMoeBlock` source during planning; add a converter unit
   test pinning the convention.
