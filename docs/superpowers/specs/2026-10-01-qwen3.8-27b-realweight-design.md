# Qwen3.8-27B real-weight completion design

## Context

The Qwen3.8-27B **code** integration is already committed and green on `main`
(`libs/lsxcommon/src/qwen_dense_27b_model.{h,cpp}` on the shared
`QwenBaseModel` dense contour, registry `kType = "qwen3.8-27b"`, converter
auto-detect at `qwen_dense_convert.cpp:386`, all 8 lifecycle stages registered
in `test_model_suite_guard.cpp`).

What is **not** done is the real-weight path:

- the source checkpoint `/mnt/llm_models/models/Qwen3.8-27B` is **not
  converted** — there is no `logestix/pinned/`, so
  `test_qwen_dense_27b_selfcheck` SKIPs;
- the FSI/CODE/DET gates `test_qwen_dense_27b_{fsi,code,det}_selfcheck` have
  **no committed goldens** (`tests/fixtures/{fsi,code,det}/qwen3.8-27b.json`
  are absent), so they SKIP too.

This spec closes that gap. It is operational (run the converter, validate,
measure) plus one small piece of code: a capture loader for the `qwen3_5` VLM
checkpoint so the goldens can be captured from the **source** safetensors.

## Source checkpoint (frozen facts, 2026-10-01)

`/mnt/llm_models/models/Qwen3.8-27B`, HF `config.json`:
`architectures=["Qwen3_5ForConditionalGeneration"]`, `model_type="qwen3_5"`,
text geometry under `text_config` (hidden 5120, 64 layers, 24 Q / 4 KV heads,
head_dim 256, intermediate 17408, linear key heads 16 / value heads 48,
`linear_conv_kernel_dim` 4, `full_attention_interval` 4,
`partial_rotary_factor` 0.25, `rope_theta` 1e7, vocab 248320, `rms_norm_eps`
1e-6, bos/eos 248044). 18 BF16 shards (~54 GiB). Tensor prefixes:
`model.language_model.*` (850), `model.visual.*` (333, vision — stripped),
`mtp.*` (15, multi-token-prediction — stripped), `lm_head.weight`.

## Approach

1. **Real conversion** (stage 1/2, existing code):
   `lsxforge --qwen --input=/mnt/llm_models/models/Qwen3.8-27B
   --output=/mnt/llm_models/models/Qwen3.8-27B` (in-place `logestix/`).
   The converter auto-detects the 27B fingerprint and strips vision/MTP with
   counting. GPU-exclusive.
2. **Validation** (stage 3): `lsxfabric --localmodel <root> --validate` and
   `lsxcli --model <root> --info`.
3. **Paris gate** (stage 8): `test_qwen_dense_27b_selfcheck` must pass
   `"The capital of France is" -> "Paris"` with >=3 bit-exact cycles.
4. **Golden capture (new code, TDD)**: add a `qwen3_5` loader override to
   `tools/{fsi,code,det}_capture.py`. A plain `AutoModelForCausalLM` load of
   this VLM checkpoint is **wrong**: `qwen3_5` maps to `Qwen3_5ForCausalLM`
   whose text weights expect prefix `model.*`, while the checkpoint stores
   `model.language_model.*` — the load silently drops the language weights.
   The override builds `Qwen3_5TextConfig` from `config.text_config`,
   instantiates `Qwen3_5ForCausalLM`, and copies each shard with
   `model.language_model.` -> `model.` remapping, skipping `model.visual.*`
   and `mtp.*` (the exact shape of the existing `qwen4_exp` override).
   Capture on the 54 GiB bf16 source cannot fit the 32 GiB 5090, so the model
   is dispatched GPU+CPU via `accelerate` (750 GiB host RAM available).
5. **Gates**: run `test_qwen_dense_27b_{fsi,code,det}_selfcheck` against the
   converted model at `kOff`; a divergence is a real finding to investigate,
   never a gate to loosen.
6. **Docs/guards**: record capture recipes/outcomes in
   `docs/{FSI,CODE,DET}_SELFCHECK_FINDINGS.md`; keep
   `test_model_suite_guard` / `test_ctest_labels_guard` green. The guards are
   already wired (stages present), so no registry change is expected.
7. **Perf last, GPU-exclusive**: re-run `test_perf_baseline_qwen3_8_27b` to
   confirm the committed `30.60 t/s` entry still holds on this host.

## TDD

The capture-tool change is the only production code. Test-first: a new
`--selftest` assertion for the key-remap helper (`_load_qwen3_5`'s
`model.language_model.` -> `model.` mapping, `mtp`/`visual` skip) that fails
before the helper is written, then the helper. The existing per-tool
`--selftest` paths must stay green.

The real-weight gates themselves are executable tests that already exist; the
conversion/validation/golden steps make them run instead of SKIP. No test
assertion is relaxed to make a gate pass.

## Risks

- **Golden divergence**: the NVFP4 converted model must reproduce the source
  answer text. A mismatch is the finding; the resolution is root-cause, not
  loosening.
- **Capture cost**: bf16 27B > 32 GiB VRAM; with CPU offload the three
  prompt-sets may take tens of minutes each. Acceptable (host RAM is ample,
  one GPU job at a time).
- **Chat-template/pretrained loader**: the `Qwen3_5TextConfig` construction
  must match the checkpoint's text config exactly (including
  `mtp_num_hidden_layers`), otherwise the capture model is wrong; the
  selfcheck Paris gate independently validates the logestix conversion.

## Out of scope

Re-running the protocol stages, kernel changes, tool-calling work (already
implemented for the qwen family), and any perf tuning beyond re-verifying the
committed baseline.
