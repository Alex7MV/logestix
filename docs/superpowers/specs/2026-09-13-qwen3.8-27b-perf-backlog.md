## Estimated potential

- MLP at the 894 GB/s ceiling: 19.0 -> 11.0 ms -> step 24.7 ms -> **~40 t/s**.
- Attention GEMM part (2.4 GB) at ceiling + attention math trimmed:
  step ~21-23 ms -> **~43-48 t/s**.
- Realistic committed target: **42-50 t/s**.

## Prioritized next levers

1. **Diagnose the warprow in-model gap (518 vs 894 GB/s).** Candidates:
   L2/DRAM interleave with neighbouring kernels, x-row re-read pattern
   (each output row re-reads the 10-35 KB activation row from L2), block
   scheduling at 4352 blocks, register pressure of the 4-accumulator
   unrolled decode loop. `ncu` currently fails with ERR_NVGPUCTRPERM —
   either enable GPU performance-counter permissions or extend
   `LSX_PERF_PHASES` with per-GEMM event pairs first.
2. **Segmented warprow variant** for the fused qkv|z|a|b linear-attn GEMM
   (currently TC segment path via `seg_wgs_dev`, explicitly excluded from
   `gemv_large`). Benefits all hybrid-attention models (qwen3.8, GLM-Flash
   KDA). The segment epilogue (per-range global_scale) ports cleanly to the
   warprow kernel.
3. **Attention math track** (separate from GEMV): linear-attn gated-delta
   kernel and split-KV full attention dominate the 12 ms attention block
   once GEMMs are at ceiling. Profile-first; bit-exactness constraints
   apply (test_qwen_dense_full_attn parity suite).
4. **Head is already routed** (N=248320 > 4096 gate); no action.

## Measured dead ends (do not retry)

- **CUDA Graphs**: GPU is ~99% busy inside phase pairs; launch overhead is
  already hidden by the async queue. Expected gain ~0.
- **TC decode-specialized kernel** (`LSX_DEC_ENABLE=1`): 20.6 t/s end-to-end
  vs 27.5 baseline — regression; tile kernel stays the default.
- **GEMV threshold A/B** (`LSX_GEMV_MAX_MIB=64/128`, `LSX_GEMV_HEAD=1`):
  27.1-27.6 t/s — within noise; the 32 MiB default is right for small
  shapes, large shapes now use the dedicated `gemv_large` route.
- **`__launch_bounds__(256, 8)` / 16 rows per block** on warprow: no
  measurable change (29.3 t/s both ways).

## Reproducing the probes

Probe sources were ephemeral (/tmp); the decisive one (decode-math ceiling,
bwprobe5/6) is reproduced here. Build: `nvcc -std=c++20 -arch=sm_120 -O3
probe.cu -o probe -lcudart`; run GPU-exclusive. Cold-DRAM methodology: 16
random-filled 89 MB buffers rotated so no pass hits L2 (L2 = 96 MiB).
IMPORTANT probe pitfall: `chunks = K/32` for 16B units over a packed row of
K/2 bytes (a `K/64` version silently reads half the row and reports ~2x BW).

```cuda
__device__ __forceinline__ float e2m1(int nib){
    const int mag = nib & 7;
    float v = mag==1?0.5f:mag==2?1.0f:mag==3?1.5f:mag==4?2.0f:
              mag==5?3.0f:mag==6?4.0f:mag==7?6.0f:0.0f;
    return (nib & 8) ? -v : v;
}
__device__ __forceinline__ float e4m3(uint8_t e){
    const uint32_t x = (e >> 3) & 0xF; if (!x) return 0.0f;
    const uint32_t bits = (x + 120u) << 23; float v;
    memcpy(&v, &bits, 4); return v;
}
// one warp per output row, 8 warps/block, no shared memory, no syncthreads
__global__ void dot_decode_kernel(const __half* __restrict__ x,
        const uint8_t* __restrict__ w, const uint8_t* __restrict__ s,
        float* out, int K, int N){
    const int lane = threadIdx.x & 31;
    const int row = blockIdx.x * (blockDim.x>>5) + (threadIdx.x>>5);
    if (row >= N) return;
    const uint4* wv = reinterpret_cast<const uint4*>(
        w + (int64_t)row * (K/2));
    const uint8_t* srow = s + (int64_t)row * (K/16);
    const int chunks = K/32;               // 16B units: 32 elements each
    const int half = chunks >> 1;
    float a0=0,a1=0,a2=0,a3=0;
    const __half2* xh = reinterpret_cast<const __half2*>(x);
    for (int c = lane; c < half; c += 32)  a_dot(wv,srow,xh,c,a0,a1);
    for (int c = half + lane; c < chunks; c += 32) a_dot(wv,srow,xh,c,a2,a3);
    float acc = (a0+a2)+(a1+a3);
    for (int off=16; off; off>>=1) acc += __shfl_down_sync(~0u, acc, off);
    if (!lane) out[row] = acc;
}
// a_dot: uint4 load; sb=2*c; sc0=sc0(srow[sb]), sc1=sc1(srow[sb+1]);
// 16-iter unroll: acc_even += x*e2m1(lo)*scl; acc_odd += x*e2m1(hi)*scl.
```

## Constraints for any follow-up work

- Bit-exactness: the 27B selfcheck (`test_qwen_dense_27b_selfcheck`) pins
  top-1 "Paris" + bit-identical logits across 3 cycles — GEMV is
  tolerance-class (fast-math); any kernel change must keep the suite green
  on both `linux-debug` and `linux-release-znver4-aocc`.
- Model independence: routing changes go through `lsx_nvfp4` +
  `gpu_perf` knobs (never per-model call sites); the
  `test_model_independence_guard` consumer list must stay valid.
- Baseline discipline: improvements land via `test_perf_baseline_qwen3_8_27b`
  (kUpdate on improvement, FAIL on -3% degradation); GPU-exclusive runs.
- 48 warps/SM max on Blackwell; `-fmad=false` for bit-exact paths only.
