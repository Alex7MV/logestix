# Kimi Round-2 Implementation Plan: Cache Un-Park + MLA NVFP4 Requant + TC Batch

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Raise Kimi-K2.7-Code default decode from 1.4 t/s to the cached-path ceiling by root-causing and un-parking the device expert cache, requantizing MLA projections to NVFP4 (freeing ~8 GiB VRAM), and re-engaging the TC batch chain — with env-gates defaulted ON.

**Architecture:** Three strictly ordered steps. (A) compute-sanitizer-driven root cause of the "correct-at-upload, wrong-at-read" slot corruption in `kimi_moe_expert_cache.cu` / pass-2/3 of `kimi_moe_inference.cu`, fix with event fencing per slot lifetime, un-gate the cache. (B) Converter writes MLA projections as NVFP4 records (hard format break); loader uploads them via the fastload ring; attention GEMV calls route through the model-neutral NVFP4 layer. (C) Flip defaults: cache from free VRAM, TC batch production path, debug tumblers remain.

**Tech Stack:** CUDA 13.3 (sm_120/121), C++20, Catch2 3.16, compute-sanitizer, Arrow IPC pinned tensors, lsx_nvfp4 model-neutral layer.

## Global Constraints

- Determinism contract: run-to-run bit-exact + "Paris" selfcheck top-1. Reference re-baselined ONCE after Task B (requant legitimately changes bits); afterwards strict.
- Norms/biases/router/embeddings/lm_head NEVER requantized (AGENTS.md precision invariant).
- No backward compat for the old `logestix-kimi` format rev (hard reject).
- NVCC-incompatibility: no abseil containers in headers reachable from `.cu` TUs.
- spdlog logging only, no printf/cout in committed code (existing `fprintf` diag blocks in kimi TU are pre-existing; remove only where the plan says).
- Inference tests run SERIAL only (`ctest` without `-j`); 160-thread builds fine.
- Build: `cmake --build build/linux-release-znver4-aocc -j 160`; tests: `ctest --test-dir build/linux-release-znver4-aocc -R <pattern>`.
- The 12 `test_qwen_dense_*` executables share one OBJECT lib (`test_qwen_cu`) — after any change to shared test sources, rebuild ALL targets before running tests.
- Commit after every task; English messages; prefixes `feat:`/`fix:`/`test:`/`docs:`/`refactor:`.
- Sanitizer runs: `compute-sanitizer --tool racecheck|memcheck <cmd>`; error-exitcode 99 for scripted runs.
- All findings/parked states are appended to `docs/superpowers/specs/2026-09-08-kimi-round2-cache-mla-requant-design.md`.
